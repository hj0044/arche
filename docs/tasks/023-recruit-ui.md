# 지시서 023: 영입 화면 개편 (구역 나눔 + 검색·필터·정렬 + 상세 시트)

전제: 022가 머지된 상태(022와 겹치는 파일은 없다. 022는 하루 결과·설정·새 게임을 건드리고, 이 지시서는 콘텐츠 > 영입 탭만 바꾼다). 시안은 이미 갱신했다. 시안과 계약이 정본이다(`docs/design/ui/Recruit.html`, `RecruitSheet.html`, `contract.json`의 `Recruit`).

## 1. 문제
영입 목록이 모든 후보를 같은 큰 카드로 길게 나열해서, 계약자가 늘면 찾기도 비교하기도 어렵다.

## 2. 화면 (시안대로, 017 준수 규칙 그대로 적용)
1. **한 줄 요약**(`recruit.summary`): 영입 가능·진행 중·잠김 인원과 남은 제로. 상단 로고줄 오른쪽의 '영입 가능 N명'은 유지한다.
2. **검색줄**: 이름·초성 검색(`mercFilter.ts`의 `matchesQuery`, `choseong` 재사용), 필터 버튼(`recruit.filter`, 44px), 정렬 선택(`recruit.sort`).
   - 필터 시트는 계약자 필터 시트와 같은 컴포넌트·모양을 쓴다. 칩 그룹은 **역할, 속성, 도시, 소속**. 여러 개 선택, 지우기, 적용 결과 N명 버튼. 잠김 계약자는 정체를 모르므로 역할·속성·소속 필터에서 제외하고 도시로만 걸린다(도시는 공개 정보).
   - 정렬: 영입순(기본: 영입 가능 → 진행 중 가까운 순 → 잠김), 비용순, 레벨순, 성장 한계순. 정렬은 구역 안에서 적용한다.
3. **상태 칩**: 전체/영입 가능/진행 중/잠김, 각 인원 수 표기. 필터·검색 결과 수를 반영한다.
4. **구역 3개**(해당 인원이 0이면 구역 숨김, 상태 칩으로 하나만 고르면 그 구역만):
   - 지금 영입 가능: 큰 카드. 영입 버튼은 시트를 거치지 않고 기존 영입 확인 단계로 간다(중요 행동 확인 규칙 그대로).
   - 진행 중: 낮은 카드(68px). 진행률 %, 막대, 조건 한 줄, 비용.
   - 잠김: 4열 작은 카드. 흐린 초상, '???', 도시. 조건·정체는 공개하지 않는다(기존 규칙 유지). 눌러도 시트가 열리지 않고 도시 힌트만 보인다.
5. **상세 시트**(`recruit.sheet`): 영입 가능·진행 중 카드를 누르면 바텀 시트. 초상, 이름·역할, 도시·소속·속성, 레벨과 성장 한계, 성장률 별(021의 별 계산 재사용), 영입 조건 목록과 진행 막대, 특성 칩, '상세 보기'(계약자 상세로 이동, 영입 전 계약자도 볼 수 있어야 한다)와 '영입 · 제로 N' 버튼(52px). 조건 미달이면 버튼은 비활성이고 부족한 조건을 보여준다.
6. 요약·검색·칩은 고정, 목록만 스크롤한다. 터치 영역 44px 이상, 글자 11px 이상.
7. 필터·검색·정렬 상태는 탭을 바꿔도 유지하고 세이브에는 저장하지 않는다(화면 상태).

## 3. 구현 메모
- `recruitFilter` 같은 모듈 전역 상태와 리스너 방식은 `mercFilter.ts`에 맞춰 정리해도 된다. 화면 상태를 한 객체로 모으면 테스트하기 쉽다.
- 필터·정렬·구역 나눔은 순수 함수로 `src/ui/recruitFilter.ts`에 두고 단위 테스트한다(`riftFilter.ts` 방식).
- 엔진(`recruitInfo`, 영입 규칙, 비용, 해금)은 바꾸지 않는다.

## 4. 하지 않는 것
영입 규칙·비용·해금 조건 변경, 시안에 없는 화면 추가, 잠김 정보 공개, 계약자 화면 변경, 영입 연출(애니메이션).

## 5. 테스트와 보고
- `recruitFilter` 단위 테스트(검색 초성, 도시·역할·속성·소속 필터, 잠김 제외 규칙, 정렬 4종, 구역 나눔), `ui:check`에 `recruit.summary`·`recruit.filter`·`recruit.sort`·`recruit.card.*`·`recruit.sheet` 존재와 터치 영역 검사 추가, `ui:shots` 갱신(영입, 영입 시트, 필터 시트), `npm test`·`typecheck`·`build`.
