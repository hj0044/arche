# 지시서 020: 스킬 구조 변경 + 상태 효과 + 자객·기만자 개방 + 도움말

전제: 017b가 머지된 상태. 이 지시서는 사용자가 2026-11-24에 확정한 내용이다. 설계서(정본)에 이미 반영되어 있다(변경 로그 2026-11-24). **021(성장률·성장 속도 삭제)과 겹치는 파일이 있으니 020을 먼저 끝내고 머지·배포한 뒤 021을 시작한다.**

데이터 초안은 사용자 검수용으로 이미 만들어 두었다. 구현자는 **옮겨 담고 검증만** 한다. 값이 이상하면 고치지 말고 보고한다.
- `docs/design/skills-draft.json`(상태 효과 5종, 기본 공격 8개, 역할별 액티브 풀 6개, 역할 특성, 신규 특성 24개, 자객·기만자 기본값)과 `skills-draft.md`(읽기용 표)
- `docs/design/roster-v2-draft.json`(36명의 스킬 배정, 특성, 신규 6명 프로필·기본 스탯. `growthRates`·`stars`·`growthPowerRatio`는 021에서 쓰므로 이 지시서에서는 무시)
- UI 시안(정본): `docs/design/ui/` 최신본. 특히 `MercDetail.html`(스킬 구역), `Battle.html`(상태 아이콘), `HelpSheet.html`, `Help.html`, `Settings.html`(도움말 행), `contract.json`. 017의 준수 규칙(시안과 다르게 만들지 않는다, `ui:shots`·`ui:check`)을 그대로 적용한다. 성장률 구역(`merc.growth`)은 021에서 만든다. 이 지시서에서는 건너뛴다.

## 1. 스킬 구조 (설계서 §전투 [확정] 변경)
- 유닛마다 **기본 공격 1개 + 액티브 3개**. 액티브는 역할 풀 6개에서 계약자별로 3개를 배정한다(`roster`의 `skills: [id, id, id]`). 패시브는 스킬이 아니라 특성이다.
- 데이터: `roles.json`의 `skills`(3개 고정)를 `basicSkill`(1개)와 `skillPool`(6개)로 바꾼다. `skills.json`은 초안의 기본 공격 8개와 풀 48개를 담는다(기존 6개 역할의 기존 스킬 id는 그대로 이어진다).
- 몬스터·병사·라이벌 병력은 같은 틀을 쓴다. 몬스터는 지금처럼 역할 기본(기본 공격 + 풀의 앞 2개)로 시작해도 된다(`unit.ts`의 `skills: [...role.skills]` 자리에서 처리). 몬스터에 상태 효과를 거는 스킬은 이 지시서에서 만들지 않는다.
- 자동 전투의 스킬 선택은 지금 방식(쿨다운이 돈 스킬을 우선순위로)을 유지하고, 새 종류에 대한 기본 규칙만 더한다 [제안, 임시]: 치유·정화는 체력 70% 이하 아군이 있을 때, 보호막은 보호막이 없는 가장 약한 아군에게, 표식·약화 스킬은 아직 걸리지 않은 대상에게, 강화는 지금처럼. 규칙은 데이터(`combat.json`)에 둔다.

## 2. 상태 효과 5종 (전투 안에서만 유지, 전투가 끝나면 모두 사라짐)
`src/data/statusEffects.json`(초안 `statusEffects`)에 정의한다. 규칙(설계서 변경 로그, 임시값은 데이터):
- **기절**: 행동하지 못한다(그 라운드 행동을 건너뜀). 지속 1라운드. 풀린 다음 라운드에는 기절에 걸리지 않는다(연속 기절 방지).
- **지속 피해**: 자기 차례가 시작될 때 피해. 피해량은 걸 때의 `공격 × 위력`을 방어로 줄인 값으로 정해 두고(변동 없음) 지속 3라운드.
- **보호막**: 최대 체력(`scaleStat`이 hp) 또는 에너지공격(`eAtk`) × `ratio`만큼을 흡수한다. 피해는 보호막부터 깎는다. 지속 시간이 끝나면 남은 양은 사라진다. 보호막이 남아 있어도 체력 막대는 그대로이고 상태 아이콘으로 보인다.
- **표식**: 받는 피해 ×1.25, 지속 2라운드.
- **약화**: 주는 피해와 치유량 ×0.75, 지속 2라운드.
- 같은 효과를 다시 받으면 겹치지 않고 지속 시간을 갱신하며(더 큰 값을 채택), 지속 시간은 효과를 받은 유닛의 행동이 끝날 때 1씩 줄어든다. 효과는 항상 적중하고 확률이 없다. 상태 효과가 있어도 시드 결정성은 유지된다(새 난수를 쓰지 않는다).
- `healer_purify`처럼 `cleanse`가 있는 스킬은 지속 피해·표식·약화를 지운다(기절은 지우지 않음).
- 새 스킬 필드: `applies: [{status, duration?}]`, `lowHpBonus`(대상 체력이 낮을수록 피해 ×(1 + 값 × (1 − 체력비율)), 즉사 없음), `ignoreTaunt`, 새 타깃 `enemyBackLowest`(후열에서 체력 비율이 가장 낮은 적, 후열이 없으면 전열), `enemyBackRow`(후열 전체, 후열이 없으면 전열). 새 종류 `shield`, `debuff`(피해 없이 상태 효과만). 일부 기존 필드는 그대로(`hits`, `enemyRow`, `enemyAll`, `scaleStat` 등).
- 후열 직격(`enemyBackLowest`, `enemyBackRow`)은 설계서 §전투의 "스킬 단위 예외"이고 도발을 무시한다(`ignoreTaunt`는 데이터가 정한다. 초안은 저격과 자객 스킬에 모두 있다). 단일 대상 기본 규칙(전열 먼저, 도발)은 그대로다.
- 특성 조건에 `targetHpBelow {threshold}`(공격 대상의 체력 비율 이하)를 추가한다(`killer_instinct`, `hunter_instinct`).
- 전투 로그·재생에 상태 효과 부여, 만료, 기절로 행동 건너뜀, 지속 피해, 보호막 흡수를 한 줄씩 남긴다.

## 3. 역할 개방과 신규 계약자 6명
- `roles.json`에서 자객(assassin), 기만자(disruptor)를 `enabled: true`로 바꾼다. 기본 스탯은 초안 `roleBase`를 `stats.json`의 `roleBase`에 추가한다.
- 구성 보너스(전위·딜러·지원)에서 자객의 그룹 `mobility`는 지금 어디에도 세지 않는다. **딜러로 센다** [제안, 임시]: `combat.json`의 `composition`에 `groupAlias: { "mobility": "damage" }`를 데이터로 둔다.
- `roster.json`에 신규 6명(m31~m36, 자객·기만자 각 3명)을 추가한다. 프로필·기본 스탯·특성은 `roster-v2-draft.json`의 `profile`, `baseStats`, `traits`, 고유 특성은 `skills-draft.json`의 `newTraits`(`unique_m31`~). `shortName`도 채운다(초안에 있음). 30명 구성 기준(고향 도시 12명씩, 속성 5명 안팎)은 초안이 맞췄다.
- 기존 30명의 `skills`도 초안대로 배정하고, 역할 특성 슬롯(②)을 초안대로 바꾼다(기존 `bulwark` 등은 일부만 새 역할 특성으로 교체). `npm run import-roster`가 이 값을 만들도록 `roster-profile.json` 또는 CSV·초안 병합 경로를 정리한다(016에서 하던 방식 그대로. CSV에는 새 6행을 추가한다. 성장 속도 열은 021에서 지운다).
- 예산 검증은 016 방식(역할 기준 전투력 대비 95~105%) 그대로. 신규 6명 포함 36명 모두 통과해야 한다.

## 4. UI
시안대로 만든다. 화면 용어는 `ui.json`/`terms.json`에 둔다.
- **계약자 상세 `merc.skills`**: '스킬' 구역(기본 공격 1 + 액티브 3 행: 종류 칩, 이름, 한 줄 설명, 쿨다운 칩). 설명은 스킬 데이터의 `description`. 설명 안의 상태 효과는 해당 아이콘(14px)으로 대체한다. 시안의 위치는 능력치 보조 줄 다음(성장률 구역 자리는 021에서 채운다. 그 전까지는 비워 두고 스킬만 보인다). 특성 아래 구역은 스크롤(`merc.scroll`)이고 헤더·하단 버튼은 고정이다.
- **전투 `battle.status`**: 유닛 초상 오른쪽 아래에 상태 아이콘(16px, 최대 4개, 넘으면 +N). 아이콘을 누르면 상태 설명 바텀 시트(`help.sheet`). 아이콘 5종은 `Help.html`/`HelpSheet.html`의 모양·색을 그대로 쓴다(`src/ui/` 공용 컴포넌트 하나, 새 상태가 늘면 데이터 행과 아이콘 추가).
- **도움말 `Help`**: 설정(`settings.help` 행)에서 진입. 항목은 데이터 `help.json`(제목, 부제, 본문 블록)에서 만들고 새 항목은 행 추가다. 상태 효과 항목의 본문은 `statusEffects.json`에서 생성한다. 항목: 상태 효과, 속성 상성, 역할(8개), 전열과 후열, 위험도(5구간), 성장과 특성(021 전까지는 성장 한계와 특성만). 문구는 설계서의 용어(계약자, 표시명)를 쓴다. 용어 검색은 제목·본문 부분 일치. 펼친 항목은 한 번에 하나.
- `contract.json`에 맞춰 `ui:shots`·`ui:check`를 갱신한다(Help, HelpSheet 시안이 추가됨. 시트 시안은 전투 위의 오버레이). 저장 화면·다른 화면의 모양은 바꾸지 않는다.

## 5. 세이브
세이브 형식 버전을 올린다(v9). 옛 세이브는 불러오지 않는다(개발 중 규칙, 마이그레이션 없음). 전투 안의 상태 효과는 저장하지 않는다.

## 6. 하지 않는 것
고유 스킬(캐릭터별 스킬, `signatureSkill` 칸만 데이터에 비워 둔다), 스탯 성장률(021), 성장 속도 삭제(021), 역할 간 상성 배율, 상태 효과 저항, 몬스터의 상태 효과 스킬, 밸런스 조정(보고만).

## 7. 테스트와 보고
- 상태 효과 규칙별 단위 테스트(기절 면역, 갱신, 지속 시간 만료 시점, 보호막 흡수 순서, cleanse, lowHpBonus 상한, 후열 직격 대상 선택과 도발 무시, `targetHpBelow`), 같은 시드 같은 결과, 한 전투에서 유닛이 연속으로 기절하지 않는지.
- 36명 예산 검증, 데이터 검증(스킬 id, 풀 6개, 3개 배정이 풀 안에 있고 중복 없음, 역할 특성 3개).
- `npm run balance`와 `npm run days`를 변경 전후로 돌려 **표로 보고**한다(조정하지 않는다). 특히 자객·기만자 포함 파티의 승률, 위험도 5구간 분포(015 목표 대비), 기절·표식 스킬이 승패에 미친 영향, 조합 보너스 변화.
- 스킬 풀의 수치는 모두 임시값이고 플레이 후 조정한다. 어색한 값(위력, 쿨다운, 지속)은 `docs/open-questions.md`에 모아서 올린다.

## 8. 완료 조건: 머지와 배포까지 (AGENTS.md 확정 규칙, 이 지시서의 일부)
1. 위 검사가 통과한 PR을 연다(테스트, 타입 검사, 빌드, `ui:check`).
2. 사용자 확인을 기다리지 않고 바로 `main`에 머지한다. 결정이 필요한 항목은 PR 본문과 `docs/open-questions.md`에 적되 머지를 막지 않는다.
3. Render 배포가 `live`가 된 것을 확인한다. 실패하면 고쳐 다시 머지한다.
4. 최종 보고는 "배포 완료", 배포 커밋, 7항의 표와 결과, compare 이미지(계약자 상세, 전투, 도움말, 시트), 미해결 결정 목록으로 한다.
