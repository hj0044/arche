# 지시서 016: 계약자 용어, 스탯 세분화, 특성 시스템

배경: 사용자 확정(2026-11-23)과 Claude 토론의 결과다. 같은 역할·같은 레벨이면 용병 스탯이 완전히 같아서 수집의 개성이 약했다. 이번에 (1) 화면 용어를 바꾸고, (2) 스탯을 세분화하고, (3) 용병별 기본 스탯과 레벨 획득형 특성을 넣는다. UI 개편은 017이고, 이번 UI 변경은 최소한이다. 옛 세이브는 신경 쓰지 않는다(AGENTS.md): 세이브 버전만 올린다.

## 확정된 것 (사용자 결정)
- **용병 → 계약자**: 화면에 보이는 이름만 바꾼다. "용병단"(배경 `mercenary_company`)과 "떠돌이 용병"(배경 `wanderer`)은 세계관 속 직업명이라 그대로 둔다. 영어 id는 바꾸지 않는다.
- **역할명(표시)**: 방패→수호자, 전사→투사, 사수→저격수, 술사→마도사, 치유사→사제, 지휘관→전술가, 암습자→자객, 교란자→기만자. id는 그대로.
- **스탯**: 핵심 6개(체력, 물리공격, 물리방어, 에너지공격, 에너지방어, 속도), 보조 3개(치명타율, 치명타 피해율, 회피율), 특수 7개는 자리만 만든다(아래 3).
- **용병별 기본 스탯을 직접 적는다**. 역할은 범위(바운더리)만 정한다. 개성의 근거는 배경·고향·성격이다.
- **특성**: 레벨마다 하나씩 획득. 종류는 공통(단순), 역할, 배경, 종족, 속성, 고유 등으로 다양하게. 나중에 특성 강화(단계)를 얹을 수 있게 설계한다.
- 위 항목의 수치와 효과는 전부 **임시값**이고 데이터 표로 둔다. 새 설정(체질 없음, 특성, 보조·특수 스탯)은 설계서에서 [제안]이다.

## 작업 목록

### 1. 용어 표와 표시 이름
- `src/data/terms.json`을 만든다(예: `{ "merc": "계약자" }`). 화면에 보이는 "용병" 글자는 이 표를 읽게 한다. 이름을 또 바꿀 때 데이터 한 줄만 고치면 되게 하는 것이 목적이다.
- 한국어 조사가 어긋나지 않게 `josa(단어, "을/를")` 같은 작은 도구를 두고 용어가 들어간 문장에 쓴다(계약자는 받침이 없고 용병은 있다). 테스트: "계약자를/계약자가/계약자는", 받침 있는 단어와 없는 단어 모두.
- `roles.json`의 표시 이름을 위 표대로 바꾼다. 하드코딩된 역할명·"용병" 글자(화면, 로그, 테스트 기대값)를 찾아 용어 표나 데이터를 읽게 바꾼다. 코드 식별자·주석·id·파일명은 건드리지 않는다.
- `AGENTS.md`의 "언어와 표기"에 한 줄을 이미 추가해 두었다. 구현자는 그 규칙을 따른다.

### 2. 스탯 세분화 (`stats.json` 구조 변경)
핵심 6개: `hp`(체력), `pAtk`(물리공격), `pDef`(물리방어), `eAtk`(에너지공격), `eDef`(에너지방어), `spd`(속도).
보조 3개: `crit`(치명타율, 비율), `critDmg`(치명타 피해율, 배율), `eva`(회피율, 비율).
- 비율 스탯은 0.05 같은 소수로 저장한다. 기본 치명타 피해율 1.5, 상한 `critMax` 0.8, `evaMax` 0.5 같은 상한도 데이터.
- 레벨 성장: 핵심 5개는 기존 성장률(체력·공격·방어 0.035, 속도 0.01)을 그대로 쓴다(공격·방어는 종류별로 같은 률). 보조 3개는 레벨로 성장하지 않는다. 용병별 값, 특성, (나중의) 훈련·장비로만 변한다.
- 스킬에 `damageType`(`physical` | `energy`)을 둔다. 물리 스킬은 물리공격 대 물리방어, 에너지 스킬은 에너지공격 대 에너지방어로 계산한다(기존 방어 상수 공식과 "공격자 레벨의 방어 성장률만큼 커지는 상수" 규칙을 두 종류 모두에 적용). 치유 스킬은 에너지공격에 비례하게 한다(`scaleStat`을 데이터로). 기본 배정(구현자가 스킬을 보고 조정, 기록): 수호자·투사·저격수·자객은 물리, 마도사·사제는 에너지, 전술가·기만자는 에너지(보조 효과 위주).
- 역할 기본값(`roleBase`)은 몬스터와 일반병사가 계속 쓴다. 기존 4스탯을 새 6스탯으로 옮기는 시작 규칙(구현자가 조정 가능): 역할의 주 공격(물리 역할은 물리, 에너지 역할은 에너지) = 기존 공격, 부 공격 = 기존 공격의 40%. 방어는 두 종류의 평균이 기존 방어와 같도록 역할 성향에 따라 ±30%로 나눈다(수호자는 물리방어가 높고 마도사는 에너지방어가 높다).
- **밸런스 보존 기준**: 이 변경은 승패를 흔든다. `npm run balance`로 같은 레벨·등급 승률을 변경 전(`origin/main`)과 후로 나란히 보고하고, 같은 구성에서 승률 변화가 ±5%p 안이 되게 역할 기본값을 맞춘다. 맞추지 못하면 멈추고 보고한다. 이 기준을 맞춘 뒤의 추가 밸런스 조정은 하지 않는다.
- 몬스터(`monsters.json`)도 같은 6+3 스탯 틀을 쓴다. 몬스터 등급 배율은 핵심 6개에 곱한다. 공허 몬스터의 보조 스탯은 낮게(치명 0.05, 회피 0.0~0.05) 둔다.
- **판정 순서와 난수**: 공격 하나가 난수를 쓰는 순서를 고정한다: 피해 변동 → 회피 → 치명타. 능력치 값에 상관없이 세 값을 항상 순서대로 뽑아 난수 소비량이 값에 따라 달라지지 않게 한다. 전투 전용 난수 스트림을 쓰고, 같은 시드는 같은 결과여야 한다(테스트). 치유는 회피·치명타 대상이 아니다. 회피하면 피해 0이고 로그에 "회피"로 남긴다.

### 3. 특수 스탯 (자리만, 효과 없음)
`stats.json`에 `special` 목록을 두고 모두 `enabled: false`로 둔다. 키는 `pen`(방어 관통: 적 방어력 일부 무시), `lifesteal`(생명력 흡수: 가한 피해 일부를 체력으로 회복), `dmgReduce`(피해 감소: 최종적으로 받는 피해 추가 감소), `shieldBoost`(보호막 강화), `healBoost`(회복량 증가: 치유 스킬 효율), `counter`(반격 확률), `critRes`(치명타 저항: 적의 치명타 발동 억제). 이름은 괄호 안 한글. 이번에는 값 칸, 데이터 검증, "켜지지 않은 스탯은 전투에 영향 없음" 테스트까지만 한다. 효과는 구현하지 않는다.

### 4. 최종 스탯 계산 한 곳
`computeEffectiveStats(unit, context)`를 `src/engine/`에 둔다: 기본 스탯(용병별 값 또는 역할 기본값) × 레벨 성장 → 특성 효과 → (나중의) 훈련·장비 → 상한 적용. **전투, 전투력, 위험도 추정이 모두 이 함수를 쓴다.** 전투력에는 치명타(평균 피해 배수 1 + 치명타율 × (치명타 피해율 − 1))와 회피(받는 피해 1 − 회피율의 역수 효과)를 기댓값으로 반영하고, 가중치는 `combat-power.json`에 둔다. 위험도 추정은 보이는 정보만 쓰는 원칙을 그대로 지킨다.

### 5. 용병별 기본 스탯 (`roster.json`)
- 용병 30명 각자 `baseStats`(핵심 6 + 보조 3의 절대값, 레벨 1 기준)를 가진다. 역할별 바운더리와 예산을 데이터로 둔다.
  - 바운더리(`roleBounds`): 역할 기본값 대비 배율 범위. 시작값은 체력 0.7~1.4, 공격(주·부 각각) 0.6~1.5, 방어(종류별) 0.7~1.4, 속도 0.8~1.25. 방어는 피해 공식에서 영향이 크므로 범위를 좁게 둔다. 보조: 치명타율 0.02~0.20, 치명타 피해율 1.3~1.8, 회피율 0~0.15.
  - 예산: `combat-power.json`의 가중치로 계산한 레벨 1 전투력이 같은 역할 기준 전투력의 95~105% 안에 들어와야 한다. 데이터 검증 테스트로 막는다. 한쪽을 높이면 다른 쪽이 낮아져 순수 상위호환이 안 생기게 하는 장치다.
- **처음 값은 Claude가 계산해 둔 초안을 그대로 쓴다**: `docs/design/roster-stats-draft.json`(사람이 읽는 표는 `roster-stats-draft.md`). 구현자는 이 JSON의 `baseStats`와 `traits`를 `roster.json`에 옮기고, 바운더리·예산 검증 테스트가 통과하는지만 확인한다. 어긋나는 값이 있으면 **고치지 말고 보고**한다(숫자는 사용자가 정한다). 따라서 `gen-roster-stats` 스크립트는 만들지 않는다. 이후 숫자는 사람이 직접 고치는 값이다.
  - 초안 계산 규칙(참고): 성향 태그 배율 적용 → 바운더리 안으로 자름 → 전투력 예산 100%로 정규화(핵심 6스탯에 같은 배율을 반복 적용 후 다시 자름). 30명 모두 예산 99.6~100.4%.
- 용병 상세에서 쓰는 비교 화면(018 이후)은 이번에 만들지 않는다. 다만 최종 스탯과 특성 목록은 상세 화면에서 글자 목록으로 보이게 한다(최소 UI).

### 6. 특성 시스템
**데이터** `src/data/traits.json` (특성 한 행):
`id`, `name`, `category`(`common` | `role` | `background` | `race` | `element` | `unique`), `description`(자동 생성이 아닌 한글 설명), `allowed`(역할·배경·종족·속성 id 목록 또는 `owner` 용병 id), `tags`(나중의 시너지용 빈 배열 가능), `maxRank`(지금은 1), `ranks`(단계별 효과 배열, 지금은 1단계만), `upgrade`(강화 비용, 지금은 `null`).
- 한 단계는 `effects` 배열이다. 효과 하나는 `{ trigger, condition?, effect }`.
  - trigger: `always`, `battleStart`(선택 `rounds`: 지속 라운드 수), `firstAction`, `hpBelow`(`threshold`), `roundStack`(`perRound`, `max`).
  - condition: `advantage`(속성 상성 유리), `enemyElement`(속성 id), `row`(`front`|`back`).
  - 구현에서 더함(지시서 018 기록): trigger `fromRound`(`round`: 그 라운드부터, 끈기), condition `disadvantage`(상대 공격이 나에게 상성 유리, 적응력).
  - effect: `{ kind, stat?, value, scope }`. kind는 `statMul`, `statAdd`, `damageMul`, `damageTakenMul`, `healMul`. scope는 `self` | `allies`(allies는 `always`/`battleStart`에만 허용).
- 알 수 없는 trigger/condition/kind는 **데이터 검증에서 실패**한다(조용히 무시하지 않는다). 새 특성은 행 추가만으로 늘어야 한다.
- 폭주 방지 상한: 특성으로 인한 스탯 배율 합 상한, 치명타율·회피율·피해 감소 상한을 `traits.json`의 `caps`에 둔다.

**획득**: 슬롯 해금 레벨을 데이터로 둔다(시작값 `[5, 15, 25, 35, 45, 55, 65]`, `progression.json` 또는 `traits.json`). 용병은 `roster.json`에 슬롯 순서대로 `traits: [id, ...]`를 가진다. 레벨이 슬롯 해금 레벨 이상일 때 그 슬롯의 특성이 활성이다. 레벨업으로 새로 해금되면 결과·로그에 "새 특성: ○○"를 남긴다. 성장 한계가 높을수록 슬롯을 더 채우게 된다(한계 35는 4개, 70은 7개). 슬롯 수보다 짧은 목록은 빈 슬롯으로 둔다.

**시작 규칙(구현자가 따르되 데이터로)**: 슬롯1 공통 → 슬롯2 역할 → 슬롯3 배경 → 슬롯4 고유 → 슬롯5 속성 → 슬롯6 종족 → 슬롯7 공통(상위). 아래 표는 이 규칙대로 채우는 초안이다.

**강화 대비(이번엔 구현하지 않음)**: 세이브에 용병별 `traitRanks: { [특성 id]: 단계 }`(없으면 1단계)를 둔다. `ranks`에 단계가 더 있으면 그 효과를 쓴다. 강화 화면·비용은 만들지 않는다. 세이브는 버전 8로 올린다(옛 세이브 무시. 015가 7을 먼저 써서 8, 지시서 018에서 고침).

**특성 초안 표** (효과 수치 모두 임시값, `value`는 설명의 수):

| 종류 | 이름 | 효과 |
|---|---|---|
| 공통 | 강건함 | 체력 +6% |
| 공통 | 연마된 솜씨 | 물리공격 +5% |
| 공통 | 집중력 | 에너지공격 +5% |
| 공통 | 단련된 몸 | 물리방어·에너지방어 +4% |
| 공통 | 민첩 | 속도 +5%, 회피율 +2%p |
| 공통 | 감각 | 치명타율 +3%p |
| 역할 | 버팀목(수호자) | 체력 40% 이하에서 물리방어·에너지방어 +30% |

### 7. 최소 UI
- 용병 상세: 최종 스탯 9개를 글자 목록으로, 특성 슬롯을 "이름 + 설명" 목록으로 보여주고 아직 해금되지 않은 슬롯은 "Lv ○ 해금"으로 보여준다. 레벨업 때 새 특성 알림.
- 위 외의 화면 개편은 하지 않는다(017). 용어와 역할명 변경은 모든 화면에 반영한다.

### 8. 테스트
- 데이터: 용병 30명 모두 `baseStats`가 바운더리·예산 안에 있다. 특성 id 참조가 모두 존재하고, 종류별 `allowed` 조건(역할·배경·종족·속성·owner)을 만족한다. 알 수 없는 효과 종류는 실패한다. 특수 스탯은 켜지지 않는다.
- 결정성: 같은 입력과 같은 시드로 전투 결과(치명타·회피 포함)가 같다. 능력치와 무관하게 난수 소비 순서가 같다.
- 전투: 물리 스킬은 물리방어, 에너지 스킬은 에너지방어를 쓴다. 치유는 회피·치명타 대상이 아니다. 치명타 피해율과 상한이 적용된다.
- 특성: 슬롯 해금 레벨에서 효과가 켜진다. `hpBelow`·`firstAction`·`roundStack`·`battleStart`(지속 라운드)·`advantage`·`allies` 범위의 동작. 상한이 지켜진다.
- 최종 스탯 계산 한 곳: 전투와 전투력, 위험도가 같은 값을 쓴다.
- 세이브: 버전 8, `traitRanks` 직렬화·복원, 옛 버전은 "지원하지 않는 세이브".
- 용어: `josa`, 용어 표를 바꾸면 화면 문구가 따라간다.

## 하지 않는 것
- 특수 스탯 효과, 특성 강화(단계 올리기) 기능, 종족·출신·인연 시너지, 훈련 방향·장비 보너스, 화면 개편(017), 위 밸런스 보존 기준 외의 수치 조정.
