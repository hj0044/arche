# 지시서 004: 1차 검수 반영

Codex 1차 검수(`docs/reviews/2026-11-20-1차검수.md`)의 오류와 UI 의견을 반영하고, 그 과정에서 사용자가 새로 정한 규칙 5가지를 구현한다. 정본은 설계서이고, 결정은 설계서 변경 로그의 2026-11-20 행이다. 문서와 코드가 다르면 문서가 맞다. 충돌하거나 비어 있는 곳은 임의로 정하지 말고 `docs/open-questions.md`에 적고 보고한다.

**시작 전 확인**: 003(징조 표식)이 main에 들어간 뒤에 시작한다. 003과 이 지시서의 3번(리프트 카드 보상)이 같은 리프트 화면과 코드를 건드린다. 003이 아직이면 멈추고 보고한다.

## 새로 확정된 규칙 (사용자 결정, 2026-11-20)

- [확정] 개방자 주인공은 파티에 넣을 수 있지만 파견에 반드시 포함할 필요는 없다. 주인공은 한 번에 한 파티에만 속한다. 이 규칙은 `AGENTS.md`에 이미 반영했다.
- [확정] 편성 화면에 자동 편성 기능을 둔다. 규칙은 [제안]이라 바꿀 수 있고, 바꾸면 보고한다.
- [확정] 부상 중인 용병은 레벨업할 수 있고, 파견 중인 용병은 복귀할 때까지 레벨업할 수 없다.
- [확정] 길드 이름과 주인공 이름에는 길이 제한을 두지 않는다. [제안] 긴 이름은 화면에서 말줄임으로 표시한다.
- [확정] 파견은 버튼 한 번으로 보내고 별도 확인 창은 두지 않는다. 대신 편성 화면에 복귀 예정일을 보여준다.

## 작업 목록

### 1. 세이브 가져오기 검증 (검수 오류 1)

- 파일에서 불러오기는 슬롯에 기록하기 전에 봉투(버전, 종류)와 필수 상태 필드(`resources`, 날짜, 시드, 용병, 리프트 등)를 모두 검증한다.
- 검증에 실패하면 슬롯을 만들지 않고, 화면에 필드 경로가 들어간 오류를 보여준다(예: `state.resources 없음`).
- 필수 필드 목록은 코드에 흩어 두지 말고 스키마 한 곳에서 정의한다.
- 테스트: 정상 v2, 이전 버전(v1 거부 유지), `resources` 없는 v2, 그 밖의 필드 누락 몇 가지.

### 2. 주인공 파견 규칙 (검수 오류 2, 규칙 변경)

- 주인공 없이도 파견할 수 있는 현재 동작이 이제 맞다. 편성 검사에서 "주인공 필수" 조건이 있다면 넣지 않는다.
- 주인공이 이미 다른 파견 중이면 다른 파티에 넣을 수 없어야 한다. 화면에서도 파견 중 표시를 하고 선택할 수 없게 한다. 없다면 추가한다.
- 테스트: 주인공 없는 파티 파견 가능, 주인공이 파견 중일 때 다른 파티 편성 거부, 주인공이 복귀하면 다시 편성 가능.

### 3. 리프트 카드 보상 = 정산 (검수 오류 3)

- 카드에 보이는 보상과 승리 정산이 같은 계산 함수를 쓰게 한다. 몬스터 레벨 배율과 안정화 통로 배율을 포함한다.
- 카드에는 "승리 시" 금액으로 표시한다. 철수 보상은 별도 값이 있으면 따로 표기한다.
- 안정화 통로의 보상 안내 문구는 `stablePassageRewardRatio` 값으로 만든다("절반" 고정 문구 금지).
- 테스트: 같은 리프트에서 카드 표시값과 실제 승리 정산이 일치(일반 리프트와 안정화 통로 둘 다).

### 4. 하드코딩 제거 (검수 오류 4)

- 자동 저장 보관 개수(3)는 정책 데이터로 한 번만 정의하고, 저장 코드와 화면 문구가 같은 값을 읽는다.
- 리프트 카드의 속성 태그와 편성 화면의 상성 안내는 몬스터 데이터와 속성 표에서 만든다. 어둠 같은 고정 표시를 코드에 두지 않는다.
- 이 작업 중 찾은 다른 하드코딩된 조정 수치도 같은 방식으로 옮기고 보고한다.

### 5. 레벨업 규칙

- 파견 중인 용병은 레벨업을 막는다. 부상 중인 용병은 허용한다. 엔진에서 막고, 화면에서는 이유를 보여준다("파견 중에는 레벨업할 수 없음").
- 테스트: 파견 중 거부, 부상 중 허용, 복귀 후 허용.

### 6. 이름 길이 제한 제거

- 새 게임 화면의 길드 이름 16자, 주인공 이름 12자 제한을 없앤다. 빈 이름만 막는다.
- 긴 이름이 목록, 카드, 전투 재생에서 레이아웃을 깨지 않게 말줄임으로 표시하고, 390×844에서 확인한다.

### 7. 자동 편성

- 편성 화면에 "자동 편성" 버튼을 둔다. 결과는 편성 칸에 채워지고 사용자가 직접 고칠 수 있다.
- 규칙 초안: 가용 용병(부상, 파견 중 제외)에서, 선택한 리프트의 알려진 정보(속성 상성)와 구성 보너스(전위, 딜러, 지원)를 기준으로 고른다. 후보 점수와 가중치는 데이터 표로 둔다.
- 엔진의 순수 함수로 만들고(`src/engine/`), 같은 입력이면 같은 결과가 나온다. 동점은 용병 id 순으로 정한다.
- 개방자 모드에서 주인공을 넣을지는 가용하면 포함하는 쪽으로 하고, 이 선택은 보고한다.
- 테스트: 결정성, 부상·파견 중 제외, 가용 인원 부족 시 있는 만큼만 편성, 전위·딜러·지원이 가능하면 모두 갖춤.

### 8. 파견 확인과 복귀일

- 확인 창은 두지 않는다. 편성 화면에 복귀 예정일(또는 소요 일수 범위)과 현재 유지비 부담을 보여준다.
- 복귀 예정일이 확정값인지 범위인지는 리프트 데이터에 따른다. 어느 쪽인지 보고한다.

### 9. 영입 확인에 유지비 표시

- 영입 확인 화면에 "영입 후 길드 하루 유지비"와 "수입 없이 버틸 수 있는 일수"를 보여준다. 계산은 엔진 함수로 만들고 화면은 값만 표시한다.

### 10. UI 개선 (390×844 기준)

- 인접 컨트롤(전열/후열 이동, 빼기, 도시와 모드 전환)의 세로 터치 영역을 44px 이상으로 맞춘다.
- 편성 화면: 후보를 추가해도 다음 후보가 밀리지 않게 한다. 편성 요약은 화면에 고정하거나 후보 목록 위에 짧게 둔다.
- 리프트 카드: 첫 줄에 레벨, 마감, 소요를 우선 두고, 몬스터 목록과 보상 세부는 접어 둔다. 한 손으로 읽기 쉬운 밀도를 목표로 한다.
- 전투 재생
  - 같은 이름의 몬스터는 번호를 붙여 구분한다(예: 껍데기 수호자 1, 2).
  - 열 카드는 인원 수에 맞춰 폭을 늘려 이름이 잘리지 않게 한다.
  - 최신 행동은 고정된 한 줄로 보여주고, 누적 로그는 라운드별로 묶는다.
  - ×4 속도에서 놓친 행동을 볼 수 있게 한 행동씩 넘기기(스텝)를 둔다. [제안]
- UI 변경은 390×844에서 직접 보고 확인한다. 색만으로 구분하지 않는다.

## 하지 않는 것

- 수치 조정(영입비, 유지비, 몬스터 레벨 범위, 성장 곡선)은 하지 않는다. 밸런스는 사용자의 플레이 이후에 정한다. 이 작업이 수치를 바꿀 수밖에 없으면 멈추고 보고한다.
- 카게야마 쇼(12번) 조정, 징조 시스템, 2단계 이후 기능은 건드리지 않는다.
- 설계서와 설정집은 고치지 않는다. 충돌과 공백은 보고만 한다.

- 위 항목마다 테스트가 있고 `npm test`, `npm run typecheck`, `npm run build`가 통과한다.
