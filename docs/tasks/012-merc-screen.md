# 지시서 012: 일괄 레벨업, 용병 화면 개선, 정렬·검색·필터, 훈련 배치 접근성, 011 보완

사용자 요청(2026-11-20), 플레이 후기("어디서 배치하는지 모르겠다"), 011 결과 분석에서 나온 보완점을 묶은 작업이다. 정본은 설계서의 육성과 변경 로그 2026-11-20 마지막 행이다. 문서와 코드가 다르면 문서가 맞다. [확정]은 지켜야 하는 규칙, [제안]은 바꿔도 되지만 보고, [미정]은 구현하지 말고 질문한다. 충돌하거나 비어 있는 곳은 임의로 정하지 말고 `docs/open-questions.md`에 적고 보고한다.

**011이 끝난 뒤의 작업이다(011은 main에 반영됨).** 011이 복귀 보고에 넣은 "레벨업 가능" 표시 옆에 이 지시서의 일괄 레벨업 버튼을 둔다.

## 확정된 것 (사용자 결정)
- [확정] 일괄 레벨업 기능을 둔다.
- [확정] 용병 화면에 정렬과 색인(검색·필터) 기능을 둔다.
- [확정] 용병 화면을 더 보기 좋게 다듬는다.

## 하지 않는 것
- 수치 조정은 하지 않는다. 레벨업 비용과 경험치 곡선은 그대로다.
- [확정] 기존 레벨업 규칙은 그대로다: 파견 중에는 레벨업할 수 없고, 부상 중에는 할 수 있다. 길드 소속만 한다.
- 정렬·필터 상태는 세이브에 넣지 않는다(화면 상태).

## 작업 목록

### 1. 일괄 레벨업
- [제안] 규칙: 레벨업이 가능한 용병을 대상으로, 가장 낮은 레벨부터 한 단계씩 반복한다. 매번 "지금 레벨업 가능한 용병 중 레벨이 가장 낮은 한 명(같으면 id 순)"을 골라 한 단계 올리고, 더 이상 가능한 용병이 없을 때까지 계속한다. 그래서 아르케가 모자랄 때 낮은 레벨 용병이 먼저 오르고, 경험치가 여러 레벨치 쌓인 용병은 여러 번 오른다. 같은 입력이면 같은 결과다(난수 없음).
- 엔진에 순수 함수(예: `levelUpAll(tables, state)`)를 두고, 기존 `canLevelUp`과 `levelUp`을 그대로 써서 규칙이 어긋나지 않게 한다. 결과로 새 상태와 단계별 기록(누가 몇 레벨에서 몇 레벨로, 쓴 아르케)을 돌려준다.
- 용병 화면 길드 탭 위쪽에 버튼을 둔다: "일괄 레벨업 (N명, 아르케 M)". 예상 인원과 아르케는 지금 상태로 미리 계산해 보여주고, 대상이 없으면 비활성으로 두고 이유를 한 줄 적는다(경험치 부족 또는 아르케 부족).
- 누르면 바로 실행하고 결과 요약을 보여준다("N명 총 M레벨, 아르케 −X"와 용병별 목록). 파견 확인 창과 같은 이유로 확인 창은 만들지 않는다.
- 011의 복귀 보고 "레벨업 가능" 표시 옆에도 같은 버튼을 둔다(같은 컴포넌트, 같은 함수).

### 2. 용병 화면 보기 좋게
- [제안] 길드 탭 카드 구성(390×844, 한 손 조작 기준):
  - 1줄: 이름, Lv, 오른쪽에 상태(출전 가능, 부상 + 회복일, 파견 중, 훈련소 배치, 레벨업 가능).
  - 2줄: 속성·역할 태그, 충성도 배지(오늘 거부 표시 포함).
  - 3줄: 경험치 막대와 "다음 레벨까지 N". 레벨업 가능하면 강조한다. 성장 한계에 도달했으면 "한계".
- 속성은 색만으로 구분하지 않고 글자도 함께 쓴다(기존 태그). 터치 영역 44px 이상, 글자 12px 이상.
- 길드 탭 위쪽에 요약 한 줄: "출전 가능 N · 부상 N · 파견 N · 훈련 N".
- 영입 탭은 영입비와 잠김 상태를 오른쪽에 두고, 고향·세력, 성장 한계·속도는 보조 줄로 줄여 정보 밀도를 낮춘다. 고향이 거점 도시인 용병을 먼저 보여주는 기본 순서는 유지한다.
- 구체적인 모양은 구현자가 정하고 스크린샷으로 보고한다.

### 3. 정렬·검색·필터
- 정렬(길드 탭) [제안]: 레벨 높은 순(기본), 레벨 낮은 순, 이름, 역할, 속성, 충성도 낮은 순, 출전 가능 먼저, 레벨업 임박(필요 경험치 대비 보유 비율 높은 순). 영입 탭은 고향 먼저(기본), 영입비 낮은 순, 레벨 높은 순, 이름. 정렬이 같으면 id 순이다(결과가 흔들리지 않게).
- 필터 칩 [제안]: 역할, 속성, 상태(출전 가능, 부상, 파견 중, 훈련 중, 레벨업 가능). 축 사이는 AND, 같은 축 안에서는 하나만 고른다. 영입 탭에는 기존 세력 칩을 그대로 둔다.
- 검색 [제안]: 이름 부분 일치와 한글 초성 검색("ㄱㅌㅅ"로 "강태산"). 초성 변환은 순수 함수로 분리해 테스트한다.
- 칩과 정렬 항목의 목록은 데이터(역할 표, 속성 표)에서 만든다. 새 역할이나 속성을 데이터 행으로 추가하면 화면 수정 없이 칩이 생겨야 한다. 정렬 항목 목록도 코드 상수가 아니라 표로 둔다(`ui.json` 또는 새 파일).
- 결과가 없으면 "조건에 맞는 용병이 없습니다"와 "필터 해제" 버튼을 보여준다.
- 용병 상세에 들어갔다가 돌아와도 정렬·필터·검색 상태가 유지된다(세이브에는 저장하지 않는다).

### 4. 훈련 배치 접근성
- 용병 상세에 "훈련소에 배치 / 배치 해제" 버튼을 둔다. 기존 규칙을 따른다(부상 중 배치 불가, 파견 중 불가, 칸이 가득 차면 불가이고 이유를 표시한다).
- 훈련소를 아직 짓지 않았으면 같은 자리에 "거점에서 훈련소를 건설하면 배치할 수 있습니다"와 거점 화면으로 가는 버튼을 보여준다.
- 훈련소 칸 수와 현재 배치 수를 용병 화면 요약(2번)에서 볼 수 있게 한다.

### 5. 테스트
- `levelUpAll`: 낮은 레벨부터, 아르케 부족 시 그 순서로 멈춤, 한 용병이 여러 번 오름, 성장 한계에서 멈춤, 파견 중 제외, 부상 중 포함, 같은 입력이면 같은 결과.
- 일괄 레벨업이 한 명씩 `levelUp`을 반복한 결과와 같다(규칙 일치).
- 초성 검색, 이름 부분 일치, 정렬의 동률 처리, 필터 AND 조합.
- 새 역할·속성 행을 가진 합성 데이터에서 칩이 자동으로 생긴다.
- 훈련 배치 버튼: 부상, 파견 중, 칸 가득 참, 훈련소 미건설 각각의 표시.
- 6번 항목의 테스트(위 각 항목)와 함께, 390×844 브라우저에서 길드 탭, 영입 탭, 용병 상세, 일괄 레벨업 결과, 홈의 레벨업 한 줄, 편성 화면의 "지금 해제"를 직접 확인하고 스크린샷을 보고한다.

### 6. 011 보완 (011 결과 분석에서 나온 것)

**6-1. 탐지소 보상 범위가 숨은 레벨을 드러내는 문제 수정** (011 작업 중 발견, 지시서 008 규칙 보완)
- 문제: 흐린 보상 범위가 실제 보상(실제 몬스터 레벨로 늘어난 값) 둘레에 놓여서, 범위 위치로 숨은 레벨을 일부 추측할 수 있다. 위험도는 보상을 쓰지 않아 영향이 없다.
- [제안] 수정: 탐지소가 보상을 정확히 보여 주지 않는 레벨(Lv1~2)에서는 보상 범위를 **보이는 레벨 범위에서 계산**한다. 즉 보이는 몬스터 레벨 범위의 양 끝(최소·최대)에서 각각 보상 범위(`rift-tiers.json` 보상 범위 × 레벨 보정)를 구해 합친 범위를 보여준다. 이렇게 하면 보이는 정보만으로 만든 값이라 숨은 값이 새지 않는다. 정확한 보상은 지금처럼 Lv3에서 보여준다.
- `visibleRift`가 순수 함수라는 규칙(보이는 정보만 반환)을 유지하고, 흐림 오프셋 저장은 그대로 둔다(세이브 버전 변경이 필요하면 구현자가 정하고 보고한다).
- 테스트: 보이는 레벨 범위가 같고 실제 레벨만 다른 두 리프트는 같은 보상 범위가 나온다. 실제 보상은 항상 보이는 보상 범위 안에 있다. Lv3에서는 정확한 값이다.

**6-2. 레벨업 가능 상태를 계속 보이게 하기**
- 문제: 011의 복귀 보고 레벨업 표시는 "오늘 경험치를 받은 용병"만 보여서, 경험치가 찼는데 아르케가 모자라 못 올린 용병은 다음 날부터 사라진다(플레이 검수에서 경험치 376인데 최초 레벨에 머문 용병이 있었다).
- [제안] 하단 탭의 "용병"에 레벨업 가능한 용병 수 배지를 붙이고, 길드 홈에 "레벨업 가능 N명 · 일괄 레벨업" 한 줄을 둔다. 아르케가 모자라 못 올리는 용병이 있으면 "경험치는 찼지만 아르케 부족 N명"을 함께 보여준다.
- [제안] 복귀 보고와 일괄 레벨업 미리보기에 합계 줄을 둔다: "합계 필요 아르케 A, 보유 B → N명 가능". 용병마다 따로 판정한 표시가 여럿을 다 올릴 수 있다는 오해를 주지 않게 한다.

**6-3. 편성 화면에서 훈련 중인 용병 바로 해제**
- 011의 "훈련 중 N명은 파견할 수 없습니다 · 배치 해제하러 거점으로" 연결 옆에 "지금 해제" 버튼을 둔다. 눌러서 해당 용병의 배치를 즉시 풀고(기존 해제 함수 사용) 후보 목록에 바로 나타나게 한다. 해제하면 그날은 쉰 날이고 경험치가 없다는 기존 규칙은 그대로다.

**6-4. 위험도 계산 성능 확인**
- 구현자 측정은 헤드리스 브라우저에서 클릭당 40~110ms였다. 실제 폰은 더 느리다. 브라우저 개발자 도구의 CPU 4배 제한에서 편성을 바꿀 때와 리프트 목록을 열 때의 계산 시간을 재서 보고한다. 200ms를 넘으면 입력이 멈춘 뒤 계산하거나 모의 전투 횟수(`combat-power.json`)를 줄이는 방법을 정하고 보고한다.

**6-5. 위험도 구간이 넓을 때의 표시 (조사만, 구현하지 않는다)**
- 리프트 목록에서 "안전 ~ 무리 (추정)"처럼 구간이 넓으면 판단에 도움이 덜 된다(탐지소 Lv1에서 흔함). 실제 플레이에서 구간이 얼마나 자주 넓게 나오는지(전체 리프트 중 구간이 3단계 이상인 비율)를 `npm run days` 같은 도구로 세어 보고만 한다. 표시 방식 변경은 사용자의 플레이 이후에 정한다.
