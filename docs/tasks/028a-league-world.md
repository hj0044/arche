028을 셋으로 나눈 첫 번째다. **화면 없이 엔진과 데이터, 시뮬레이션만** 만든다.

|---|---|
| **028a (이 문서)** | 이름 생성기, NPC 용병단 세계 생성, 시즌 정산(승강·변동), 순위 계산, 세이브 |
| 028b | 우리 용병단 연결(공적 점수, 승강), 시즌 말 보상, 등급 → 리프트 공급 가중치·보수 배율 |

설계서 "리그와 세계 확장"(용병단 리그, NPC 용병단, 랭킹과 보상)이 근거다. [확정]은 지키고, [제안]은 임시값으로 구현하되 바꾼 곳은 PR 본문에 적는다. 수치는 모두 데이터 표다. 같은 입력과 시드면 같은 결과다.

## 1. 데이터

### 1-1. `src/data/league/rules.json` (새 파일)
- 등급 5개(미진, 약진, 중진, 강진, 격진): id, 이름, 순서, 팀 수(10, 10, 8, 8, 4 — 우리 용병단 1곳 포함), 승격 수, 강등 수(설계서 값: 격진 하위 1 강등, 강진 상위 1 승격·하위 2 강등, 중진·약진 상위 2 승격·하위 2 강등, 미진 상위 2 승격), 등급별 공적 점수 곡선 파라미터(시즌 30일 동안의 누적 곡선 모양과 난수 폭).
- 규모 단계 5개: 최소·최대 인원(4~5, 5~10, 10~20, 20~40, 41~70, 상한 70은 임시), 개인 전력 평균 계수(작은 팀은 높고 큰 팀은 낮음), 상위 강자 수(큰 팀도 약 5명).
- 시즌: 길이 30일, 시즌 말 동시 정산.
- 시즌 변동: 규모 단계 ±1 이동 팀 비율(20~25%), 승격팀은 커질 확률·강등팀은 줄어들 확률 보정, 인원 변동 폭, 계약자 이적·은퇴·신입 비율, 민간 용병단 이름 변경 확률(설정 용병단은 이름 고정), 전체 규모 분포 보정 강도.
- 초기 규모 분포 목표: 6, 11, 11, 8, 3팀(39팀).

### 1-2. 이름 생성기 데이터
- `src/data/names/`는 D01(+D03 보완)이 만든 풀을 읽는다. 문화권 가중치 = 인구 비례 50% + 균등 50%, 한 문화권 상한 15%, 대륙별 최소 비율(`rules`에 표로 둔다. 임시값: 대륙 7개 각 5% 이상). 문화권 표의 `order`(family_first/given_first), `surnameCount`를 따른다.
- 유명 인물 이름 조합을 거르는 목록은 `src/data/names/blocklist.json`(성+이름 쌍 배열, 처음엔 빈 배열 가능)으로 두고 생성 때 걸러낸다.
- 국적(문화권)과 고향(도시)은 별개다. 이름을 만든 문화권은 국적 필드로 저장하고, 역할·속성·성격에 영향을 주지 않는다.

## 2. 이름 생성기 (`src/engine/names.ts`)
- 입력: 시드, 문화권(생략하면 가중치로 뽑음), 성별, 톤(선택). 출력: `{ cultureId, surname, given, display }`. 표기 순서는 `order`를 따른다. 성이 없는 문화권 설정이나 성 2개(이베리아 등)는 `surnameCount`를 따른다.
- 같은 시드는 같은 이름. 한 번의 생성 호출에서 이미 쓴 `display`와 같지 않다(NPC 세계 전체와 우리 계약자 이름과도 겹치지 않게 사용 중 목록을 받는다).
- 이름 풀 항목은 읽기만 하고 고치지 않는다.

## 3. NPC 용병단 세계 (`src/engine/league/`)
- 시작: `teams.json` 39팀을 읽는다(설정 14, 민간 25). 규모 단계·리그 힌트(top/upper/mid/lower/any)·거점 도시·세력·컨셉을 따른다. 힌트는 등급 범위로 바꿔 배정하고 리그별 팀 수를 맞춘다(우리 용병단은 미진에서 시작하는 한 자리를 비워 둔다).
- 점수가 먼저고 구성은 나중이다: 팀마다 시즌 점수 곡선(등급 + 시즌 난수)을 먼저 뽑고, 그 곡선에 맞춰 계약자 명단과 개인 활약도 곡선을 역산한다. 작은 팀은 개인 활약도가 높고, 큰 팀은 낮되 상위 강자(약 5명)를 둔다.
- 명단: 설정 용병단은 `featured.json` 대표 인물을 포함하고 나머지는 이름 생성기로 채운다. 계약자 필드: `id, name, cultureId, gender, age, role, element, hometown, background, post?`와 활약도 곡선. 같은 유닛 틀로 나중에 확장할 수 있게 저장 형식에 `unit` 확장 자리를 열어 둔다(지금은 비움).
- 총 NPC 계약자는 약 660명이 목표다(규모 분포에서 나오는 값). 표시용이라 전투하지 않는다.

## 4. 시즌 진행과 정산
- 하루마다 NPC 팀의 점수와 계약자 활약도가 곡선을 따라 쌓인다(`advanceLeagueDay`). 곡선에는 시드 기반 난수 폭이 있다.
- 시즌 말(30일 단위) `settleSeason`: ① 최종 순위 확정 ② 승격·강등(우리 용병단 자리도 같은 규칙, 0점이어도 규칙은 동일) ③ 팀 변동: 규모 단계 이동, 인원 변동, 이적·은퇴·신입(이적하는 계약자는 이름과 기록을 유지, 은퇴는 명단에서 빠짐. "죽음·전사"라는 표현은 쓰지 않는다), 민간 용병단 이름 변경, 새 시즌 점수 곡선(등급이 바뀌면 곡선도 바뀜) ④ 전체 규모 분포 보정(한쪽으로 크게 쏠리지 않게).
- 우리 용병단 자리는 외부에서 점수를 넣는 인터페이스(`setPlayerScore`)만 둔다. 이번 지시서에서는 연결하지 않는다(028b). 기본값 0이면 미진 최하위다.

## 5. 순위 계산
- 용병단 순위(리그별, 전체), 계약자 활약도 순위(전체, 역할별 — 역할 표에서 자동, 시즌, 통산). 우리 계약자 기록(027)은 외부 입력 인터페이스로만 받는다.
- 보상 계산은 028b다. 여기서는 순위 결과만 낸다.

## 6. 세이브
- 리그 상태를 세이브에 넣는다(시드, 시즌 번호, 팀·명단·곡선, 순위 이력은 최근 5시즌). 세이브 버전을 올리고(현재 버전에서 +1) AGENTS.md 규칙대로 마이그레이션 없이 이전 버전은 "지원하지 않는 세이브"로 거절한다.
- 세이브 크기를 재서 PR 본문에 적는다(660명 + 이력). 너무 크면 곡선은 파라미터만 저장하고 값은 시드로 다시 계산한다.

## 7. 개발 도구
- `npm run league -- [시즌 수] [시드]`: 시즌마다 격진 상위 3팀, 승강 목록, 규모 분포, 이름·문화권 분포를 요약해 출력한다.
- `npm run names -- [개수] [시드]`: 이름 샘플 출력(문화권 비율 확인용).

## 8. 검증
- 결정성: 같은 시드와 시즌 수면 모든 결과가 같다.
- 구조: 리그별 팀 수(우리 자리 포함 10/10/8/8/4)가 시즌 정산을 거듭해도 유지된다. 승격·강등 수 일치. 규모 단계별 인원 범위 준수(상한 70).
- 분포: 50시즌 시뮬에서 규모 분포가 한 단계로 쏠리지 않는다(각 단계가 전체의 5% 이상), 문화권 상한 15%·대륙 최소 비율, 같은 이름 중복 없음.
- 변동: 시즌마다 일부 팀의 규모·이름·등급·명단이 실제로 바뀐다. 설정 용병단 이름은 안 바뀐다. 이적하는 계약자의 이름·기록 유지.
- 점수 곡선: 작은 팀 개인 평균이 큰 팀보다 높고, 큰 팀에도 상위 강자가 있다. 4~5명 최상위 팀과 20~30명 최상위 팀이 모두 나올 수 있다(시드 표본에서 확인).
- 세이브 왕복(저장 후 불러오면 같음), 이전 버전 거절. `npm test`, `typecheck`, `build` 통과. 기존 `balance 400`과 전투 결과는 그대로.

## 9. 하지 않는 것
화면(028c), 우리 용병단 점수 연결·보상·리프트 공급 가중치(028b), 다른 세계와 횡단 구간, 시즌 특별 규칙, 시즌 이벤트, 도시 확장, 자동 소탕(029), 이름 풀 수정.

## 10. 확인할 것(멈추지 말고 PR 본문과 `docs/open-questions.md`에)
- 곡선 모양과 난수 폭, 규모 변동 확률 같은 임시값의 근거와 표본 결과.
- 설정 14팀의 힌트를 등급으로 바꿀 때 애매했던 곳.
- D01 열린 질문(인도네시아·몽골·인도 남부·이베리아의 성 순서·생략, 중성 이름이 적은 지역)을 이름 생성기에서 어떻게 처리했는지.
