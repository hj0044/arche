# 지시서 005: 2차 검수 반영

Codex 2차 검수(`docs/reviews/2026-11-20-2차검수.md`)에서 남은 오류와 UI 문제 3건을 고친다. 작은 작업이다. 정본은 설계서이고 문서와 코드가 다르면 문서가 맞다. 충돌하거나 비어 있는 곳은 임의로 정하지 말고 `docs/open-questions.md`에 적고 보고한다.

## 작업 목록

### 1. 세이브 의미 검증 (검수 오류)

몬스터가 없는 리프트(`enemies: []`)를 가진 손상 세이브가 가져오기를 통과해 카드에 `제로 -∞`가 뜨고 다음 날 진행이 멈춘다. 필드 하나만 막지 말고, 같은 종류의 문제를 한꺼번에 막는다.

- **값 범위 검사**: 숫자는 유한해야 하고, 레벨·소요 일수·적 수 같은 값은 최소값을 지켜야 한다. 최소값은 데이터 표의 범위를 읽어서 쓰고 코드에 박지 않는다. 리프트의 `enemies`는 1개 이상이다.
- **참조 검사**: 리프트의 몬스터 id가 몬스터 데이터에 있는지, 파견과 파티의 용병 id가 세이브의 용병에 있는지, 같은 용병이 한 파티에 두 번 들어 있지 않은지, 도시·세력·등급·배경 id가 데이터에 있는지, 복귀 보고와 파견이 가리키는 리프트가 있는지를 확인한다. 이 밖에 같은 종류의 참조가 보이면 함께 넣고 보고한다.
- 참조 검사는 데이터 표가 필요하므로 스키마 파일과 분리된 검증 단계로 만들고, 가져오기와 불러오기 둘 다 슬롯에 기록하거나 게임을 시작하기 전에 거친다. 데이터 표는 인자로 받아 저장소 쪽이 엔진이나 UI에 의존하지 않게 한다.
- 실패하면 지금처럼 필드 경로가 들어간 오류를 보여준다(예: `state.rifts[0].enemies 비어 있음`). 보여 줄 개수 규칙은 기존과 같다.
- 테스트: 검수 재현(`r1`의 `enemies`를 `[]`로), 존재하지 않는 몬스터 id, 존재하지 않는 용병 id를 가진 파견, 같은 용병이 중복된 파티, 숫자 필드에 음수나 0, 정상 세이브와 `npm run make-audit-save`로 만든 세이브가 통과하는지.

### 2. 전투 재생: 긴 이름 넘침

- 현재 행동 한 줄에서 행위자 이름에만 폭 제한과 말줄임을 적용해, 스킬 이름과 피해값이 항상 보이게 한다.
- 누적 로그는 공백 없는 긴 문자열도 컨테이너 안에서 줄바꿈한다.
- 복귀 보고 문장과 다른 화면의 긴 문자열도 같은 문제가 없는지 확인한다. 있으면 같이 고치고 보고한다.
- 확인: 공백 없는 160자 이름의 주인공으로 전투를 재생하고, 현재 행동과 로그가 가로로 넘치지 않는 것을 390×844에서 직접 본다.

### 3. 터치 영역

- 재생 속도 버튼의 최소 너비를 44px로 맞춘다.
- 이 김에 앱 전체에서 높이나 너비가 44px 미만인 눌리는 요소가 더 있는지 점검하고, 있으면 고치거나(공간이 없으면 이유와 함께) 보고한다.

## 하지 않는 것

- 수치 조정은 하지 않는다. 밸런스는 사용자의 플레이 이후에 정한다.
- 설계서와 설정집은 고치지 않는다. 충돌과 공백은 보고만 한다.
- 2단계 이후 기능은 건드리지 않는다.

## 완료 기준

- 1번에는 위 테스트가 있고 `npm test`, `npm run typecheck`, `npm run build`가 통과한다.
- 직접 확인한다: 몬스터 없는 리프트를 넣은 세이브 가져오기가 거부되고 오류에 경로가 나온다, 긴 이름 전투 재생, 속도 버튼 크기.
- `npm run days`로 같은 시드 결과가 이전과 같은지 비교한다(수치를 안 바꿨으니 같아야 한다).
- 보고는 한국어로, 항목별 한 줄과 함께 추가로 발견해 고친 것, 문서와 충돌한 곳, 확인하지 못한 것을 적는다.
