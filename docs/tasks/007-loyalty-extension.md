# 지시서 007: 충성도 확장 (대기 하락, 무소속 영입 이동, 모든 세력 공통 틀)

006(충성도)에 이어 세 가지를 더한다. 정본은 설계서의 "충성도" 절과 변경 로그 2026-11-20 마지막 행들이다. 문서와 코드가 다르면 문서가 맞다. [확정]은 지켜야 하는 규칙, [제안]은 바꿔도 되지만 보고, [미정]은 구현하지 말고 질문한다. 충돌하거나 비어 있는 곳은 임의로 정하지 말고 `docs/open-questions.md`에 적고 보고한다.

## 확정된 규칙 (사용자 결정, 2026-11-20)

- [확정] 오래 출전하지 않은 용병의 충성도는 서서히 내려간다(대기 하락). 쉬는 날 상승은 출전 없이 7일까지만 준다.
- [확정] 무소속 용병은 다른 세력에 영입되어 소속이 바뀔 수 있다. 영구 소멸은 없고, 그 세력에서 다시 영입할 수 있다.
- [확정] 충성도는 모든 세력의 용병이 같은 틀로 가진다. 2단계에서 길드 밖 용병은 영입 시점의 시작값만 갖고 시뮬레이션하지 않는다. 3단계 라이벌 AI가 같은 틀을 그대로 쓴다.
- [제안] 대기 하락: 출전 없이 7일까지는 쉬는 날 상승, 7일을 넘기면 하루 −0.5. 성향별 가중치는 야망형 ×2, 안정형 ×0.25, 나머지 ×1.
- [제안] 무소속 영입 이동: 하루가 끝날 때 무소속 용병마다 하루 2% 확률로 이동하고, 이동할 세력은 세력별 가중치(도시 영향력)로 정한다. 충성도 이탈 직후 3일은 보호 기간이다.
- 길드 소속 용병의 갈취, 라이벌의 회유, 라이벌 AI, NPC 세력 용병의 충성도 시뮬레이션은 만들지 않는다. 나중에 얹을 자리는 막지 않는다.

## 작업 목록

### 1. 데이터 (모든 수치는 표로 분리, 아래 값은 임시)

- `loyalty.json`에 대기 하락을 넣는다: `restMaxDays` 7, `idleDecay` −0.5, 성향별 `idleDecay` 가중치(야망 2, 안정 0.25, 없으면 1).
- `poaching.json`(같은 폴더, 이름은 구현자가 정해도 됨)을 만든다: 하루 확률 0.02, 보호 일수 3, 이동 세력 가중치 규칙, 이동 대상에서 제외할 세력(무소속).
- 새 성향, 새 세력, 새 요인은 행 추가로 늘릴 수 있어야 한다.

### 2. 모든 세력 공통 틀

- 세이브의 충성도 필드를 길드 용병에만 두던 것을, 주인공을 제외한 모든 용병이 갖도록 바꾼다. 길드 밖 용병은 영입 시 시작값(60)을 갖고, 하루가 끝나도 변하지 않는다.
- 하루 정산의 충성도 변동, 거부, 이탈 판정은 "어느 세력의 용병을 시뮬레이션할지"를 데이터로 정한다(지금은 길드만). 3단계에서 다른 세력을 켤 수 있어야 한다.
- 이탈하면 무소속으로 옮기고 충성도는 시작값으로 되돌려 보관한다(삭제하지 않는다).
- 세이브 버전 처리는 구현자가 정한다(버전을 올리고 마이그레이션 권장). 스키마와 의미 검증도 맞춰 바꾸고 이유를 보고한다.

### 3. 대기 하락

- 용병마다 연속으로 쉰 일수를 센다. 쉰 날이란 그날 파견 중이 아니고 부상 중이 아닌 날이다(거부한 날도 쉰 날). 파견을 나가거나 부상을 입으면 0으로 돌아간다.
- 연속 쉰 일수가 `restMaxDays`(7) 이하인 날은 지금처럼 쉬는 날 상승을 적용하고, 넘긴 날부터는 쉬는 날 상승 대신 대기 하락(성향 가중치 포함)을 적용한다.
- 이 값들은 길드 용병에게만 적용한다.

### 4. 무소속 용병 영입 이동

- 하루가 끝날 때 길드 소속이 아닌 무소속 용병마다 시드로 이동을 판정한다. 시드는 세이브 시드, 날짜, 용병 id로 만든다. 같은 입력과 시드면 같은 결과다.
- 충성도 이탈 직후 보호 일수 동안은 판정에서 제외한다. 이탈한 날짜를 용병 상태에 저장한다.
- 이동할 세력은 가중치로 정한다. 가중치는 그 용병의 고향 도시에서의 세력 영향력(`factions.json`의 `cityInfluence`)을 쓴다. 무소속 세력은 대상에서 제외한다. 영향력이 모두 0이면 동률로 처리하고 이 처리를 보고한다.
- 이동하면 소속 세력만 바뀐다. 영입 해금 조건은 그대로이고, 영입비는 새 세력의 배율로 달라진다(기존 영입비 공식 유지).
- 시작 구성에서 무소속인 용병과 개방자 모드에서 빠진 후보도 같은 규칙을 따른다.
- 이동은 하루 결과에 "○○가 △△에 합류" 한 줄로 보여준다. 길드 소속이었다가 이탈한 용병이면 같은 줄에 그 사실이 드러나게 한다(예: "이탈했던 ○○가 △△에 합류").

### 5. 화면 (390×844 세로 기준)

- 용병 상세: 연속 쉰 일수(대기 N일)와 대기 하락 중이라는 표시, 최근 변동 요인에 "대기 하락"이 나온다. 색만으로 구분하지 않는다.
- 하루 결과: 이동 소식을 한 줄로, 눈에 띄지만 길지 않게.
- 영입 화면: 이동한 용병은 새 소속이 보이고 영입비가 그에 맞게 바뀐다.
- 터치 영역 44px 이상, 정보 밀도는 접기와 요약으로 관리한다.

### 6. 테스트

- 대기 하락: 쉬는 날 상승이 7일까지만 적용되고, 8일째부터 하락한다. 성향 가중치(야망 ×2, 안정 ×0.25)가 적용된다. 파견 또는 부상으로 연속 일수가 0으로 돌아간다. 0~100을 벗어나지 않는다. 주인공에는 적용되지 않는다.
- 이동: 시드 결정성, 보호 기간 중 이동 없음, 길드 소속 용병과 주인공은 대상 아님, 무소속이 아닌 용병은 대상 아님, 이동 후 소속이 바뀌고 영입할 수 있고 영입비가 세력 배율로 달라진다, 영구 소멸 없음.
- 모든 용병이 충성도를 갖는 세이브 스키마, v→새 버전 마이그레이션, 이탈 시 충성도 시작값 보관.
- 결정성 회귀 확장: 이동과 대기 하락이 일어나는 길드에서 15일 동안 매일 저장 왕복하며 상태·이벤트가 같다.

### 7. 비교표 (수치는 바꾸지 않는다)

- `npm run loyalty-sweep -- [일수] [시드 수]`를 추가한다. 값 조합별 시뮬레이션 결과를 마크다운 표로 출력한다.
- 조합은 미납 하락(−5, −8, −10), 위험 구간 거부 확률(0.25, 0.4), 이탈 확률(0.2, 0.35), 대기 하락(−0.5, −1), 무소속 이동 확률(0.01, 0.02, 0.04)에서 의미 있는 조합을 구현자가 고른다. 조합이 너무 많으면 한 번에 한 값씩 바꾸는 방식으로 줄인다.
- 40일과 80일, 시드 6개 이상으로 돌리고, 각 조합의 이탈 수, 거부 수, 구간 분포, 대기 하락이 일어난 횟수, 무소속 이동 수를 표로 만든다.
- 결과 표를 `docs/balance/2026-11-20-loyalty-sweep.md`로 커밋한다(이 폴더는 새로 만든다). 이전에 요청받아 만든 비교표가 있으면 그 내용도 같은 파일 앞부분에 옮겨 적는다.
- `loyalty.json`과 `poaching.json`의 기본값은 지시서의 임시값 그대로 둔다. 값을 고르는 것은 사용자의 플레이 이후다.

## 하지 않는 것

- 수치 최종 조정은 하지 않는다. 위 수치는 임시값이다.
- 라이벌 AI, 갈취, 회유, NPC 세력 용병의 충성도 시뮬레이션, 거점 시설, 일반병사는 만들지 않는다.
- 설계서와 설정집은 고치지 않는다. 충돌과 공백은 보고만 한다.
