# 지시서 017b: UI 후속 + 018 후속 연결

전제: 017(UI 시안 적용)과 018(전투 검수 반영)이 머지된 상태. 이 지시서는 사용자가 2026-11-24에 확정한 후속 항목을 한 번에 처리한다. 시안·계약은 이미 갱신되어 있다(`docs/design/ui/` 최신본이 정본, 특히 `Main.html`, `Content.html`, `Merc.html`, `contract.json`, `shots/ref/`). 017의 준수 규칙(0항 전체)과 검증 도구(`ui:shots`, `ui:check`, 정적 검사)를 그대로 쓴다. 시안과 다르게 만들고 싶어도 만들지 말고 보고한다.

## 1. UI: 시안 갱신분 반영 (필수)
1. **홈 '최근 보고' 한 줄 카드**(`main.report`): 파견 현황 아래, 하루 넘기기 버튼 위. 가장 최근 하루 결과(일차, 리프트 이름, 성공/실패, 제로 증감, 경상 수)와 '재생' 버튼(터치 44px, 시안 크기 유지). '재생'은 그 보고의 전투 재생을 연다(지금 홈에 있던 최근 보고 목록·재생 링크가 이 카드 하나로 줄어든다). 보고가 없으면 구역을 숨긴다. 홈의 길드 배너 높이가 시안에서 줄었다(50px). 시안 HTML의 값을 따른다.
2. **콘텐츠 리프트 카드 배지**: 배너 왼쪽 위 라벨(도시 · 종류) 옆에 '소규모'(소규모 변형일 때), '징조'(징조가 보일 때. 탐지소 Lv3 정보). 시안의 모양·색을 따른다. 징조·소규모 판정은 지금 엔진이 쓰는 값을 읽는다.
3. **계약자 화면 필터 버튼**(`merc.filter`): 검색줄 가운데(44px). 누르면 바텀 시트에서 **역할·속성·상태** 칩을 고른다(여러 개 선택, 지우기, 적용 결과 수 표시). 기존 필터 칩 줄(전체/대기/부상/충성 낮음/일괄 레벨업)과 함께 쓰이며, 시트에서 고른 조건은 칩 줄과 AND로 결합한다. 역할·속성 목록은 데이터 표에서 만든다(새 역할·속성 행이 자동으로 늘어난다). 이미 있는 `mercFilter.ts`에 조건을 추가하고 단위 테스트를 둔다.
4. **전투 화면 뒤로 버튼 없음**: 지금 있다면 시안대로 없앤다(시안 `Battle.html`에는 없다). 끝내는 길은 '결과 보기'와 '건너뛰기'뿐이다. 재생 중 실수로 나가는 일은 없다.
5. **계약자 카드 짧은 이름**: 카드(계약자 그리드, 파티 후보 그리드, 슬롯)에서는 긴 이름이 잘린다(예: "빅토리아 레이놀…"). `roster.json`에 `shortName`(카드용 표시 이름) 필드를 추가하고 30명을 채운다. 규칙 초안: 외국식 이름은 이름(앞)만, 동아시아식은 성 포함 전체가 3~4자면 그대로, 길면 이름만. 예: 빅토리아 레이놀즈 → 빅토리아, 다니엘 브루크스 → 다니엘, 시라유키 하루카 → 하루카, 카를로스 멘도사 → 카를로스, 미겔 오르티스 → 미겔, 타치바나 아키라 → 아키라, 모리타 겡지 → 겡지, 나카무라 사에 → 사에, 미야자와 유우 → 유우, 쿠로세 렌 → 렌, 카게야마 쇼 → 쇼, 하야시 켄타로 → 켄타로, 루시아 페르난데스 → 루시아, 올리버 그레이 → 올리버, 타카기 다이치 → 다이치, 아오키 미츠키 → 미츠키, 마커스 홀리스 → 마커스, 토니 루소 → 토니, 제이 박 → 제이, 마야 참 → 마야, 나머지 한국 이름(강태산, 윤서아, 오진석, 신지호, 백서린, 임소하, 마도현, 구만수, 유도진, 안예린)은 그대로. 상세 화면·시트·로그에는 전체 이름을 쓴다. `ui:check`에 "카드 이름이 말줄임(…)으로 잘리지 않는다(30명 전원, 픽스처 기준)" 검사를 추가한다.
6. 위 1~5에 맞춰 `ui:shots`를 다시 찍고 compare 이미지를 PR에 첨부한다(홈, 콘텐츠, 계약자, 전투 4장 이상). `ui:check` 전부 통과.

## 2. 018 후속 연결
1. **96회 상세 위험도 연결**: 파티 편성 화면 요약의 위험도와 승률 범위에만 `estimateRisk(..., { detail: true })`를 쓴다(`src/ui/screens/PartyBuilder.tsx`의 요약, `src/ui/partyInfo.ts`의 승률 범위). 리프트 목록은 12회 그대로. 중앙값 약 25ms, 최대 약 80ms이므로 계산 중에는 UI가 멈추지 않게 파티 변경마다 한 번만 계산(디바운스 150ms 이내)하고, 계산 전에는 직전 값을 흐리게 보여 준다.
2. **치명타 피해율 상한 2.0 확정**: `stats.json`과 `open-questions.md`의 표기를 [제안]에서 [확정]으로 바꾼다.
3. **전투 변동성 기준값 유지 확정**: 피해 변동 0.9/1.1, `speedJitter` 0. `docs/open-questions.md`의 해당 항목을 확정으로 바꾼다.
4. **공허전에서 발동하지 않는 속성 특성(11개)**: 속성 친화류 특성에 **상시 소효과**를 추가한다. 상성 조건부 효과(지금 값)는 그대로 두고, 같은 특성에 "자기 속성 스킬로 주는 피해 +4%(상시)" 효과를 더한다(데이터 `traits.json`의 `effects`에 행 추가, 수치는 임시값). 속성 조건이 있는 다른 특성(공명, 적응력, 서리의 결정 등)은 같은 방식으로 하되 상시 효과가 어울리지 않으면 건드리지 않고 목록으로 보고한다. 변경 후 `npm run balance`를 다시 돌려 45개 구성의 변화와 보호선(압도는 압도, 무모는 무모)을 보고한다. 상시 효과가 공허전에서 실제로 발동하는지 테스트를 둔다. 상한 합산(+0.50)에 걸리는 계약자가 늘면 목록으로 보고한다.

## 3. 결정 기록 (문서)
`docs/open-questions.md`에 아래를 "확정(2026-11-24)"으로 적고 해당 "결정 대기" 항목을 닫는다.
- 접전·우세 80% 목표는 유지하되 달성은 019 후보("길드 맞춤 의뢰")로 미룬다. **019는 지금 하지 않는다.** 전투 변동성은 기준값 유지.
- 전열 공격 독점: 설계서 §5 규칙 유지, 플레이 후 재검토.
- 같은 역할 안의 강함 차이와 특성 수치 하향(P3): 플레이 후 결정.
- 전투 화면 뒤로 버튼 없음, 시안 반영 3종(최근 보고, 배지, 필터 시트), 짧은 이름.

## 4. 하지 않는 것
019(길드 맞춤 의뢰), 특성 수치 하향, 타깃팅 규칙 변경, 위험도 경계 변경, 홈·콘텐츠·계약자·전투 외 화면의 모양 변경, 시안에 없던 다른 기능 자리 추가(HP 숫자, 이전 행동 버튼, 경험치 미리보기, 정렬·등급 필터 등).

## 5. 테스트
- 새 필터 조건 단위 테스트, 짧은 이름 30명 검사, `ui:check` 전체 통과, 특성 상시 효과 발동 테스트, `npm test`·`typecheck`·`build` 통과.

## 6. 완료 조건: 머지와 배포까지 (AGENTS.md 확정 규칙, 이 지시서의 일부)
1. 위 검사가 통과한 PR을 연다.
2. 사용자 확인을 기다리지 않고 바로 `main`에 머지한다. 결정이 필요한 항목은 PR 본문과 `docs/open-questions.md`에 적되 머지를 막지 않는다.
3. Render 배포가 `live`가 된 것을 확인한다. 실패하면 고쳐 다시 머지한다.
4. 최종 보고는 "배포 완료", 배포 커밋, 1~2번 각 결과(compare 이미지, balance 전후 표, 보고 목록), 미해결 결정 목록으로 한다.
