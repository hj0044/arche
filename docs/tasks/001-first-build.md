# 작업 001 — 1단계 첫 빌드

이 문서는 Claude Code에게 맡기는 첫 작업 지시서다. 먼저 `AGENTS.md`와 `docs/design/phase1-spec.md`를 읽는다. 명세가 정본의 발췌이고, 비어 있거나 충돌하는 곳은 아래 "질문과 가정" 규칙을 따른다.

## 목표

세로 모바일 화면에서, 도시를 고르고 리프트에 용병 파티를 파견해 자동 전투 결과를 받고 용병을 키우는 한 판이 끝까지 돌아가는 1단계 빌드. Render에 정적 사이트로 배포해 폰에서 확인한다.

## 진행 방식

- 마일스톤마다 브랜치를 따고 PR을 올린다. 마일스톤 하나는 실행해서 확인할 수 있는 상태로 끝낸다.
- 각 마일스톤 끝에 무엇을 만들었는지, 어떻게 확인했는지, 남은 문제를 짧게 보고한다.
- 규칙 엔진(전투, 진행)은 화면과 분리한 순수 로직으로 만들고 자동 테스트를 붙인다.
- 사용자에게 묻는 건 명세가 [미정]이거나 충돌할 때만 한다. 나머지는 [가정]대로 진행하고 기록한다.

## 질문과 가정

- 명세의 [미정]은 구현자가 임시값으로 정하되, `docs/open-questions.md`에 "항목, 정한 임시값, 이유"를 한 줄씩 남긴다.
- 설계서·설정집과 명세가 충돌하면 임의로 고르지 않고 해당 마일스톤 보고에 올린다.
- 수치는 전부 데이터 표로 분리한다. 코드에 숫자를 박지 않는다.

## 마일스톤

### M1. 뼈대와 배포

- 기술 스택을 정한다. 제안: TypeScript, Vite, 가벼운 UI 라이브러리(React 등), 테스트는 Vitest. 정적 빌드로 Render Static Site에 올릴 수 있어야 한다. 다른 스택을 쓰면 이유를 적는다.
- 폴더 구조: 규칙 엔진, 데이터 표, 저장소, 화면을 분리한다.
- 세로 모바일(390×844 기준) 레이아웃 틀, 빈 화면 몇 개(도시 선택, 길드 홈).
- `AGENTS.md`의 "기술 스택과 명령" 섹션을 채운다(설치, 실행, 테스트, 빌드 명령).
- Render 배포 설정(`render.yaml` 또는 안내 문서)을 만든다. 실제 배포 연결은 사용자가 하므로 필요한 값을 적어준다.
- 완료 기준: 로컬 실행, 테스트 1개 통과, 빌드 성공.

### M2. 데이터 표와 전투 엔진

- 시드 기반 난수(같은 시드면 같은 결과).
- 데이터 표: 속성(상성 포함), 역할, 몬스터 등급, 리프트 등급, 전투 수치(배율, 보너스, 라운드 수), 부상 일수.
- 유닛 틀(명세 2절). 용병과 몬스터가 같은 틀을 쓴다.
- 전투 엔진(명세 5절): 열 배치, 타겟팅, 도발, 범위 공격, 행동 순서, 스킬 쿨다운, 상성, 구성 보너스와 약점, 15라운드 제한, 결과 판정, 부상 판정.
- 전투 로그를 구조화된 이벤트 목록으로 반환한다. 나중에 화면이 이를 재생한다.
- 테스트: 같은 시드 재현, 상성 배율, 열 배치와 타겟팅, 도발, 라운드 제한 철수, 구성 보너스와 약점, 부상 일수(치유사 포함).
- 완료 기준: 샘플 파티와 몬스터로 전투를 돌려 결과와 로그가 나오고 테스트가 통과한다.

### M3. 진행, 리프트, 파견

- 하루 단위 턴 진행, 날짜 흐름.
- 리프트 생성과 마감(명세 7절). 도시별로 다른 목록. 마감이 지나면 사라진다.
- 파견: 파티 편성(전열/후열 배치), 소요 일수, 동시 파견, 복귀 시 전투 계산과 결과 정산(보상, 부상, 성장).
- 용병 성장(성장 한계, 성장 속도, 최초 레벨의 개별 수치).
- 부상 중 파견 불가, 하루가 지나면 회복.
- 테스트: 마감 처리, 동시 파견, 부상 회복, 정산.
- 완료 기준: 화면 없이 엔진 테스트만으로 며칠을 진행하는 시나리오가 통과한다.

### M4. 세이브

- 버전 번호가 붙은 JSON 세이브 스키마.
- 저장소 인터페이스와 브라우저 로컬 구현(용량이 큰 방식), 파일 내보내기·불러오기.
- 수동 저장 슬롯(제한 없음), 슬롯별 자동 저장 3개 순환, 덮어쓰기 확인.
- 하루를 넘길 때 자동 저장.
- 테스트: 저장과 불러오기 왕복에서 상태가 같음, 자동 저장 순환, 버전 필드.

### M5. 화면 (세로 모바일)

- 새 게임 시작: 주인공 유형(개방자/길드 마스터 모드), 개방자 커스텀(속성, 역할), 배경 선택(효과 없음), 길드 이름, 시작 도시.
- 길드 홈: 날짜, 자원(아르케, 제로), 용병 목록, 진행 중 파견.
- 리프트 목록(등급, 마감, 소요, 보상), 파티 편성 화면(전열/후열), 파견 확인.
- 하루 넘기기, 복귀 결과 화면, 자동 전투 재생(전투 로그를 라운드별로 보여줌, 빠르게 넘기기 지원).
- 용병 상세, 세이브 슬롯 화면(수동, 자동, 덮어쓰기 확인, 내보내기·불러오기).
- UI 원칙: 한 손 조작, 터치 영역 충분히, 속성은 화면 표기명, 정보는 단계별로 펼친다.

### M6. 샘플 콘텐츠와 마감

- 용병 약 30명의 샘플 로스터(한글 이름, 속성, 역할, 개별 성장 수치), 5개 세력과 분포, 도시 2~3곳의 리프트 목록.
- 흑막 쪽 몬스터 몇 종(공허 속성, 등급별).
- 한 판을 처음부터 끝까지 돌려보고 막히는 곳, 밸런스가 극단적인 곳을 기록한다.
- `docs/open-questions.md`를 정리해 사용자가 읽고 결정할 수 있게 만든다.
- 완료 기준: 폰 화면 크기에서 한 판이 돌아가고, 배포된 주소에서 같은 동작을 확인한다.

## 보고 형식

마일스톤마다 다음을 짧게 쓴다.

1. 만든 것 (3줄 이내)
2. 확인 방법과 결과 (테스트, 실행)
3. 가정으로 정한 것 (`docs/open-questions.md`에 추가한 항목)
4. 명세와 충돌하거나 비어 있던 곳
5. 다음 마일스톤에서 필요한 사용자 결정

## 하지 않는 것

명세 14절을 따른다. 1단계 밖의 기능은 만들지 않는다. 설계서를 바꾸자고 제안하고 싶으면 보고에 적는다. 문서는 사용자가 고친다.
