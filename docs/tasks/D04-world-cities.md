# 데이터 지시서 D04: 도시 9곳 데이터와 이동 일수

대상: GPT/Codex 등 데이터 작성자. 먼저 `docs/design/world-brief-for-data.md`, `docs/tasks/README.md`의 "데이터 지시서" 절, 현재 데이터 `src/data/cities.json`, `src/data/travel.json`, `src/data/factions.json`을 읽는다. 게임은 아직 이 데이터를 읽지 않는다(도시 확장 구현 지시서에서 연결). 새 폴더 `src/data/world/`에만 만든다. 엔진·UI·기존 데이터는 고치지 않는다.

## 1. 목적

도시를 3곳에서 9곳(서울, 도쿄, 뉴욕, 런던, 라고스, 상파울루, 뭄바이, 두바이, 시드니)으로 늘릴 때 쓸 데이터를 미리 만든다: 도시 설정과 리프트 발생 값, 도시 사이 이동 일수, 세력별 도시 영향력.

## 2. 파일

### 2-1. `src/data/world/cities.json` (정확히 9행)
기존 `cities.json`과 같은 틀에 필드를 더한다.
```json
{
  "id": "london",
  "name": "런던",
  "summary": "한 줄 요약(화면에 쓰임, 40자 이내)",
  "lore": "도시 설정 2~3문장",
  "openerRate": 1.0,
  "riftSpawn": { "maxActive": 6, "dailySpawnChance": 0.42, "dailySpawnRolls": 2, "initialCount": 3, "initialGuaranteed": [{"tier": "crack", "grade": "low"}], "tierWeights": {"crack": 4, "gate": 5, "route": 1}, "levelSkew": 1.8 },
  "recruitment": { "otherHometownCostMultiplier": 1.5 }
}
```
- **서울, 도쿄, 뉴욕 3행은 기존 `cities.json` 값과 한 글자도 다르지 않게 복사한다**(밸런스를 이미 맞췄다). `lore`와 `openerRate`만 새로 더한다(서울 1.0, 도쿄 0.8, 뉴욕 1.2는 임시).
- 새 6곳(런던, 라고스, 상파울루, 뭄바이, 두바이, 시드니)의 `riftSpawn`은 아래 도시색을 따르되 값은 기존 3곳이 있는 범위 안에 둔다: `maxActive` 5~9, `dailySpawnChance` 0.35~0.75, `dailySpawnRolls` 1~3, `tierWeights`의 항로 0~2, `levelSkew` 1.5~3.0. 균열이 몰리는 도시일수록 `maxActive`·`dailySpawnChance`가 크다.
- `openerRate`: 그 도시에서 개방자(계약자)가 나오는 상대 비율. 0.5~2.0, 라고스·뭄바이처럼 몰리는 도시가 높다. 지금은 표시용이다.
- `otherHometownCostMultiplier`: 1.0~1.5. 영입이 활발한 도시는 낮다.
- 도시색(근거는 설정집 확정):
  - 런던: 오랜 가문과 기사 전통. 귀족적 분위기, 균열은 중간.
  - 라고스: 젊고 거친 개방자 출현 핫스팟. 균열이 잦고 `openerRate` 최고.
  - 상파울루: 초대형 도시, 자경단·길드 문화. 균열 수가 많다.
  - 뭄바이: 인구 밀집, 자본과 대중문화. 균열 수가 많고 영입이 활발.
  - 두바이: 에너지와 자본의 계획 신도시. 관문 비중이 높고 항로는 드물다.
  - 시드니: 고립된 항구 도시. 항로 비중이 높다.
- `summary`와 `lore`에 균열이 많은 이유를 설명하는 문장을 쓰지 않는다(원인 불명 [확정]). 국가·도시 고정관념, 실존 인물·기업·브랜드, 죽음·사망 표현, 흑막·공허·징조 언급을 쓰지 않는다. 한글만(도시 이름 포함).

### 2-2. `src/data/world/travel.json`
기존 `travel.json`과 같은 틀(`sameCityDays`, `defaultDays`, `routes: [{between: [a, b], days}]`)에 `unit`을 더한 것이다. 9곳 전체 36쌍을 모두 적는다(기본값에 기대지 않는다).
- **이동 일수는 "왕복 총 일수"로 적고 0 또는 1일이다**(사용자 확정 2026-11-26: 왕복 최장 1일). 현재 `travel.json`은 편도 일수이고 게임이 두 배로 쓰지만, 새 파일은 처음부터 왕복 기준이다. 파일 맨 위에 `"unit": "roundTrip"`을 적는다. 아르케 기반 고속 수송과 개방자의 이동 능력 지원, 항로 안정화로 이동이 크게 줄어든 세계라는 설정이다.
- 기준: 0일은 같은 지역권(당일 왕복), 1일은 먼 쌍. 1일 쌍은 전체 36쌍 중 12쌍 이하로 둔다(대륙 사이 가장 먼 조합 위주). 2일 이상은 쓰지 않는다. 실제 거리와 대륙 배치를 따르되 항로가 몰린 도시(시드니)는 이동이 조금 유리하다.
- 기존 3쌍은 서울–도쿄 0, 서울–뉴욕 1, 도쿄–뉴욕 1로 적는다. 숫자는 같지만 의미가 편도에서 왕복으로 바뀌어 실제 이동은 짧아진다(경제 영향은 도시 확장 구현 때 확인한다).
- `rationale` 필드에 위 설정을 2~3문장으로 적는다. 아직 설정집에 없는 새 설정이므로 문장 앞에 "[제안]"을 붙인다(사용자가 판단). 기존 설정(제로데이, 리프트, 개방자, 아르케)과 충돌하지 않게 쓴다.

### 2-3. `src/data/world/influence.json`
세력 6개(rrb, archon, bulwark, waypoint, indie, free)별 도시 9곳의 영향력. 세력마다 값의 합은 1.0이다(±0.001). 세력은 세계관 전용이고 이 값은 "어느 세력 인물이 어느 도시에 자주 나오는지"를 정하는 연출 가중치다(수치 효과 없음 [확정]).
```json
{ "rrb": {"seoul": 0.2, "tokyo": 0.1, "...": 0}, "archon": {"...": 0} }
```
- 기존 `factions.json`의 3도시 값은 방향 참고용이다(예: 리프트 대응국은 서울 비중이 크다, 웨이포인트는 뉴욕 비중이 크다). 새 도시도 세력 설정에 맞게 나눈다(아르콘·불워크는 두바이·도쿄·뉴욕·런던에 걸치게, 독립 강자 모임은 넓게, 무소속은 고르게).
- 모든 세력이 모든 도시에 0.02 이상은 가지게 한다(어느 도시에서도 가능성이 0이 되지 않게).

### 2-4. `src/data/world/README.md`
파일 설명, 값을 정한 기준, 새 설정([제안]) 목록, 애매했던 점.

## 3. 검증

- `src/data/world/world.test.ts`:
  - 도시 id 9개가 정확히 맞고(목록은 위 순서), 서울·도쿄·뉴욕 행의 `riftSpawn`과 `recruitment`가 기존 `cities.json`과 깊은 비교로 같다.
  - `tierWeights`가 음수 없이 합이 0보다 크다, 모든 필드가 범위 안이다.
  - `travel.json`이 `unit: "roundTrip"`이고 36쌍을 정확히 한 번씩 담으며, 값은 0 또는 1 정수, 1일 쌍은 12쌍 이하, 기존 3쌍 값이 위와 같다.
  - `influence.json`의 세력 id가 `factions.json`과 같고, 세력별 합이 1.0(±0.001), 모든 값이 0.02 이상.
  - 텍스트에 한글 외 문자, 금지 표현(죽음, 사망, 흑막, 공허, 징조)이 없다.
- `npm test`, `typecheck`, `build` 통과. 기존 데이터·엔진은 건드리지 않는다.
