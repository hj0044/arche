# 지시서 022: 외곽 임무(쉬는 계약자 자동 배치) + 플레이어 길드 마스터 전용

전제: 021(성장률)이 머지된 상태. 이 지시서는 사용자가 2026-11-25에 확정한 두 가지를 처리한다. 설계서(정본)는 이미 갱신했다. 문서와 코드가 다르면 문서가 맞다.

## 0. 설계서와의 충돌 보고 (사용자가 번복 결정, 이유는 설계서 변경 기록에 있음)
아래 [확정]은 2026-11-25에 사용자가 번복했다. 구현자는 다시 묻지 말고 새 규칙대로 만든다.
- 개방자 주인공이 파티에서 직접 싸운다 → **폐지**. 플레이어는 길드 마스터 전용, 전투 비참여, 주인공 캐릭터는 파티에도 계약자 목록에도 없다.
- 개방자 모드 / 길드 마스터 모드 분기 → **폐지**. 새 게임에 모드 선택이 없다.
- 시작 구성: 시작 계약자 후보 4명을 **모두** 시작한다(주인공 역할과 겹치는 1명 제외 규칙 삭제).
- 의뢰와 도시 계약 보류 [확정]과는 충돌하지 않는다. 외곽 임무는 의뢰 보드가 아니라 자동 배치다.

## 1. 플레이어 길드 마스터 전용
1. `Protagonist` 구조에서 `mode`, 원소, 역할, `mercId`, `PROTAGONIST_ID` 경로를 없앤다. 남기는 값은 이름과 배경(이력)뿐이며, 배경은 화면에서 쓰지 않으면 그대로 두되 새로 늘리지 않는다.
2. `newGame`은 시작 후보 4명을 전부 계약자로 넣는다(`pickCandidateToLeave` 삭제). 시작 구성이 전위·딜러·지원을 갖추는 검사는 유지한다.
3. `NewGame.tsx`에서 주인공 유형, 속성·역할 선택, 이탈 후보 안내를 없앤다. 입력은 길드 이름, 마스터 이름, 거점 도시만 남긴다.
4. `Title.tsx`, `MercDetail.tsx`, `format.ts`, `auditSave.ts`, `ui-mock.json`, 관련 테스트(`combatPower`, `review-014`, `determinism`, `mercFilter`, `riftFilter`, `riftInfo` 등)에서 주인공 참조를 정리한다. 유지비의 `protagonistUpkeep` 설정과 `progression.protagonistGrowth`는 지운다.
5. **세이브 v11**: v10 → v11 마이그레이션에서 `protagonist.mercId`가 있으면 그 계약자를 목록과 모든 파티 열에서 제거하고(파티가 비면 빈 열 유지), 진행 중 파견에 포함돼 있으면 그 파견은 해당 인원 없이 그대로 진행한다. 이 규칙을 테스트로 고정한다.
6. `AGENTS.md`의 1단계 범위 문구와 `docs/design/phase1-spec.md`의 해당 줄(122행 근처)을 새 규칙으로 고친다(사본 갱신 방법은 `docs/README.md`).

## 2. 외곽 임무 [설계서 확정(자동 배치·충성도 반응), 이름·수치는 제안]
쉬는(대기) 계약자를 하루가 끝날 때 자동으로 일에 배치하는 콘텐츠다. 전투 없이 시드로 결과가 정해진다.

- **종류 2개**: 소탕(경험치 중심), 회수(제로·아르케 중심). 이름과 종류는 데이터 행 추가로 늘릴 수 있게 `src/data/outerMissions.json`에 둔다. 모든 수치는 이 표에 둔다(임시값).
- **배치 대상**: 그날 파견에 나가지 않았고 부상이 아니며 충성도 위험 구간이 아닌 계약자. 계약자마다 종류를 하나 정한다(역할·속성 적성이 아니라 단순하게 시드 추첨, 같은 입력과 시드면 같은 결과). 지금 UI에서 '쉬는' 계약자가 곧 대상이다.
- **하루 단위**: 배치 결과는 하루가 끝날 때 정산한다. 여러 날 걸리지 않는다(1단계 단순화). 다음 날 다시 쉬는 상태면 또 배치된다.
- **보상(임시 시작값)**: 소탕은 계약자 레벨의 비례 경험치, 회수는 제로 소량과 낮은 확률의 아르케. 합산해서 결과 화면에 한 번에 보여준다. 경험치는 성장 한계를 넘지 않는다(기존 경험치 규칙 그대로).
- **경상**: 낮은 확률로 경상(부상 1단계 규칙, 기존 부상 일수 표 사용). 경상이 되면 기존 `injury` 충성도 변동이 그대로 적용된다.
- **설정 토글**: 설정 > 게임에 '자동 배치'(`settings.autoOuter`, 기본 켜짐). 끄면 계약자는 예전처럼 쉰다(쉬는 날 규칙 그대로). 토글 값은 세이브에 저장한다.
- **하루 결과 화면**: 시안 `Result.html`의 '외곽 임무' 카드(`result.outer`)를 그대로 만든다. 인원이 0이면 카드를 숨긴다. 홈 '최근 보고' 한 줄에는 넣지 않는다.
- **계약자 카드·상세**: 다음 하루 결과가 나올 때까지 별도 상태 표시는 만들지 않는다(자동이므로 관리할 것이 없다). 이 항목은 시안에 없으므로 만들지 않는다.

## 3. 충성도 반응 [확정]
- 외곽 임무에 간 날은 **쉬는 날로도 노는 날로도 세지 않는다**(`restDay` 보너스와 `idleDecay` 모두 없음, 쉬는 날 연속 일수도 끊지 않고 그대로 둔다).
- 반응은 **안 좋은 쪽만** 있다. 성향별 하루 변동은 `loyalty.json`에 `outerMission` 블록으로 둔다: 안정형 −0.5, 나머지 성향 0. 좋은 쪽 보너스는 없다.
- 결과 화면 카드의 마지막 줄에 '○○형 불만 N명'과 합계 충성도 변동을 쓴다.
- 기존 충성도 값(`idleDecay`, `restDay`, 성향 가중치)은 바꾸지 않는다. 자동 배치를 끈 상태의 동작이 예전과 같아야 한다(테스트).

## 4. 019(길드 맞춤 의뢰)와의 관계
이 지시서에 포함하지 않는다. 019는 021 이후 플레이 확인 뒤에 정한다. 단, 이름은 "맞춤 리프트"로 부르기로 했다(의뢰 보드 방식 아님). 외곽 임무와 데이터·화면을 섞지 않는다.

## 5. 하지 않는 것
전투 로직 변경, 충성도 규칙 삭제·개편, 스킬·성장 변경, 계약자별 외곽 임무 수동 배정 UI, 여러 날짜 임무, 019 구현, 밸런스 조정.

## 6. 테스트와 보고
- 시작 4명 전원 계약자, 모드 선택 없는 새 게임, v10→v11 마이그레이션(주인공 있던 세이브), 같은 시드 같은 결과(외곽 임무), 토글 끔 = 기존 동작 동일, 안정형만 −0.5, 부상·위험 구간 제외, `ui:check`(`result.outer`, `settings.autoOuter`, 주인공 문구 검색 0건), `npm test`·`typecheck`·`build`.
- `npm run days`를 021 이후와 비교해(제로·경험치 증가량, 충성도 분포) 표로 보고한다(조정하지 않는다). 외곽 임무로 파견 효율 대비 보상이 너무 크거나 작으면 수치는 바꾸지 말고 보고만 한다.
