# 데이터 지시서 D01: 계약자 이름 풀 (30개 문화권)

대상: GPT/Codex 등 데이터 작성자. 요청자: 사용자와 Claude(설계). 먼저 `docs/design/world-brief-for-data.md`와 `docs/tasks/README.md`의 "데이터 지시서" 절을 읽는다.

## 1. 목적

계약자와 NPC 용병단 구성원의 이름을 만드는 **이름 풀 데이터**를 만든다. 게임은 이 풀에서 시드 기반으로 이름을 뽑는다(뽑는 코드는 나중에 Claude Code가 짠다). 이번 작업은 **데이터 파일과 그 검증 테스트만** 만든다. 엔진, UI, 기존 데이터 파일은 고치지 않는다.

## 2. 파일과 형식

모두 `src/data/names/` 안에 둔다.

### `cultures.json`
문화권 목록. 한 문화권 = 한 행. 배치(PR)마다 그 배치의 문화권 행을 추가한다.

```json
{
  "id": "korea",
  "name": "한국",
  "continent": "east_asia",
  "population": 52,
  "order": "family_first",
  "surnameCount": [1, 1],
  "note": "한 줄 메모(선택)"
}
```

- `continent`: east_asia, southeast_asia, south_asia, central_asia, west_asia_north_africa, europe, sub_saharan_africa, americas, oceania 중 하나.
- `population`: 대략의 인구(백만 명). 아래 4절 표의 값을 그대로 쓴다.
- `order`: family_first(성이 앞) 또는 given_first(이름이 앞).
- `surnameCount`: 한 사람이 가질 수 있는 성의 개수 범위(스페인·중남미는 [1, 2], 나머지는 [1, 1]).

### `<문화권 id>.json`
```json
{
  "id": "korea",
  "surnames": [{ "text": "강", "tones": ["modern"] }],
  "names": [
    { "text": "이안", "gender": "m", "tones": ["modern"] },
    { "text": "서윤", "gender": "f", "tones": ["gentle"] },
    { "text": "하람", "gender": "n", "tones": ["modern"] }
  ]
}
```

- `text`: 한글만, 공백·하이픈·숫자 없음, 1~8자(`^[가-힣]{1,8}$`). 성과 이름은 따로 적는다(합친 형태를 쓰지 않는다).
- `gender`: m(남성), f(여성), n(성별에 구애받지 않고 쓰이는 이름).
- `tones`: 1~2개. 값은 modern(현대적이고 세련됨), noble(귀족적·고전적 격조), rugged(강하고 거친 인상), gentle(부드럽고 차분함) 중에서만 쓴다. 성에도 tones를 붙인다(성이 마땅한 인상이 없으면 modern).

## 3. 수량과 품질 기준 (문화권마다)

- 성 정확히 60개, 이름 정확히 100개(남 40, 여 40, 중성 20). 같은 문화권 안에서 성끼리, 이름끼리 중복 없음.
- 중성(n) 이름은 그 문화권에서 실제로 성별 구분 없이 쓰이는 이름이어야 한다. 마땅한 것이 모자라면 현대에 널리 쓰이는 중성적 이름을 쓰고, 억지로 만들지 않는다.
- tones 분포 기준: noble 이름은 문화권마다 최소 5개(귀족적·고전적 격조가 있는 실제 이름), rugged와 gentle도 각각 최소 5개. 나머지는 modern 위주.
- 현대에 실제로 쓰이는 이름이어야 한다. 노년 느낌의 촌스러운 이름, 시대에 뒤떨어진 이름, 한 세대 전에만 쓰던 이름은 넣지 않는다. 개성 있고 부르기 좋은 이름을 고른다.
- 성은 그 문화권에서 실제로 널리 쓰이는 성을 인구 분포를 어느 정도 반영해 고르되, 희귀한 성도 섞는다.
- 한글 표기는 외래어 표기법과 해당 언어의 원음을 따른다(중국어·일본어·베트남어 등은 현지 발음에 가깝게, 이미 굳은 통용 표기가 있으면 통용 표기). 한 문화권 안에서 표기 방식이 일관되어야 한다.
- 세계관 요약 5절의 금지 사항을 지킨다: 실존 인물·유명 가상 인물의 고유 이름 조합, 비속어와 같은 소리, 비하하는 이름, 학살자·독재자·테러범과 강하게 연결된 이름, 신성한 이름의 단독 사용 금지.
- 소수 민족, 원주민 문화권의 이름은 실제로 쓰이는 이름만 쓰고, 의미를 모를 때는 넣지 않는다.
- 국적으로 성격이나 역할을 정하지 않는다. 이 데이터에는 성격·역할 정보가 없다.

## 5. 검증 테스트 (이 지시서에서 코드로 만드는 유일한 파일)

`src/data/names/names.test.ts`를 만든다. 다음을 검사한다.
1. `cultures.json`의 모든 행은 같은 id의 풀 파일이 있고, 풀 파일은 모두 `cultures.json`에 행이 있다.
2. 각 풀: 성 60개, 이름 100개(m 40, f 40, n 20), 정규식 `^[가-힣]{1,8}$`, tones 값이 허용 목록 안이고 1~2개, 성끼리·이름끼리 중복 없음, noble·rugged·gentle 이름이 각각 5개 이상.
3. `continent`, `order`, `surnameCount`가 허용된 값이다. `population`은 양수.
4. 마지막 배치(5번)에서는 문화권 수가 정확히 30이라는 검사를 추가한다(그 전에는 넣지 않는다).
5. `src/data/names/` 안의 어느 파일에도 영문자와 숫자가 `id` 필드 외에는 나오지 않는다.

`src/data/names/README.md`에 스키마와 문화권 목록을 짧게 적는다(배치마다 갱신).

## 6. 하지 않는 것

엔진·UI·기존 데이터 변경, 이름을 뽑는 코드, 이세계 인물, NPC 팀과 인물 설정(D02에서 한다), 계약자 이름 교체(실제 캐릭터 생성 때 따로 한다).

## 7. 완료 조건: 머지와 배포까지 (docs/tasks/README.md 규칙, 이 지시서의 일부)

1. 배치마다 `npm test`, `npm run typecheck`, `npm run build`가 통과한 PR을 연다.
2. 이 데이터는 아직 게임이 읽지 않으므로 사용자 확인을 기다리지 않고 바로 `main`에 머지한다. 품질 문제는 머지 뒤에 Claude가 검수해서 수정 요청을 하고, 같은 방식으로 고친다.
3. Render 배포가 `live`가 된 것을 확인한다.
4. 보고는 "배포 완료", 배치 번호와 배포 커밋, 막힌 질문 목록으로 한다. 5개 배치를 모두 끝내면 "D01 전체 배포 완료"로 보고한다.
