# 지시서 013: 라이벌 리프트 선점(1차)과 리프트 한도 확대, 많은 리프트의 화면

세력 경쟁의 1차로 **라이벌의 리프트 선점**만 만든다. 함께 도시당 리프트를 늘리고, 리프트가 많아져도 고르기 쉬운 화면을 만든다. 정본은 설계서의 "라이벌 선점"과 변경 로그 2026-11-21 마지막 행이다. 문서와 코드가 다르면 문서가 맞다. [확정]은 지켜야 하는 규칙, [제안]은 바꿔도 되지만 보고, [미정]은 구현하지 말고 질문한다. 충돌하거나 비어 있는 곳은 임의로 정하지 말고 `docs/open-questions.md`에 적고 보고한다.

## 확정된 것 (사용자 결정, 2026-11-21)
- [확정] 세력 경쟁 1차는 리프트 선점만 만든다. 세력 평판, 영입 경쟁 확대, 라이벌 AI는 만들지 않는다(나중에 얹을 자리는 막지 않는다).
- [확정] 압박은 약하게 한다. 지금 플레이 느낌을 해치지 않고 조금씩 조인다.
- [확정] 도시당 리프트 수를 늘리고, 도시마다 따로 정한다(데이터). 리프트가 많아졌을 때의 화면(UI/UX)도 함께 설계한다.

## 사용자가 고르지 않아 정한 가정 [제안]
- 선점하는 라이벌은 이름 있는 세력이다. 리프트가 생길 때 그 도시의 세력 영향력(`factions.json`의 `cityInfluence`)을 가중치로 "영역 세력"을 하나 정해 리프트에 저장한다. 나중에 평판을 붙이기 쉽다.
- 선점 확률의 요인은 리프트 등급별 기본값과 마감 임박 보정 두 가지다(세력 영향력과 평판은 확률에 쓰지 않는다).
- 선점 손해는 리프트가 사라지는 것뿐이다(평판 없음). 알림은 하루 결과에서만 알려준다(미리 경고 표시는 하지 않는다).
- 이 가정들이 틀렸으면 사용자가 바꾼다. 구현은 값과 요인을 데이터로 분리해 쉽게 바뀌게 한다.

## 현재 상태 (측정, 자동 플레이 60일·시드 6개)
| 도시 | 한도 | 하루 생성 확률 | 평균 활성 리프트 | 한도에 닿은 날 |
|---|---|---|---|---|
| 서울 | 5 | 0.75 | 2.7 | 13% |
| 도쿄 | 4 | 0.60 | 3.1 | 49% |
| 뉴욕 | 5 | 0.60 | 3.7 | 30% |

- 서울은 한도가 아니라 **생성 빈도**가 병목이다(한도를 올려도 거의 안 바뀐다). 도쿄는 한도가 병목이다. 그래서 한도와 생성 빈도를 **함께** 도시별로 올려야 한다.
- (참고) 서울 최대 활성 수가 6으로 한도 5를 넘는 날이 있었다. 안정화된 통로가 한도에 안 세어지는 것일 수 있다. 그렇다면 그대로 두되 의도인지 `docs/open-questions.md`에 적는다.

## 규칙 [제안, 수치는 모두 임시값]

### 리프트 수
- 목표 평균 활성 리프트(선점으로 줄어든 뒤 기준): 서울 약 5.5, 도쿄 약 4.5, 뉴욕 약 5. 임시 한도: 서울 8, 도쿄 6, 뉴욕 7.
- 도달 방법은 구현자가 정한다(하루 생성 확률 올리기, 하루 생성 판정 횟수 늘리기 등). 값은 `cities.json`에 도시별로 둔다. 위 측정 방법으로 도달했는지 확인해 보고한다.

### 선점 판정
- 하루 정산에서 **마감이 있는 불안정 리프트**마다 한 번 굴린다. 안정화된 통로(마감 없음)와 이미 파견이 출발한 리프트는 판정하지 않는다. 그날 새로 생긴 리프트도 판정하지 않는다.
- 확률 = 등급 기본값 × 마감 임박 보정. 임시값: 기본값 균열 3%, 관문 2%, 항로 1%, 마감 임박 보정은 남은 2일 ×1.5, 남은 1일 ×2.
- 시드 = 세이브 시드:preempt:날짜:리프트 id. 같은 입력과 시드면 같은 결과다.
- 선점되면 리프트가 사라지고 하루 결과에 알림이 뜬다. 판정 순서는 구현자가 정하고 `docs/open-questions.md`에 적는다(마감 만료, 귀환 처리, 새 리프트 생성과의 순서).
- 이 확률이면 리프트 수명(3~15일) 동안 선점당하는 비율이 한 자릿수에서 10%대 초반이 된다. 구현 후 `npm run days`와 비슷한 도구로 실제 선점 비율을 재서 보고한다.

### 영역 세력
- 리프트가 생길 때 도시의 세력 영향력으로 영역 세력을 정해 저장한다(생성 시드에서 가져온 별도 난수 흐름. 기존 리프트 생성 결과가 바뀌지 않게 한다).
- 리프트 카드와 상세에 "○○ 영역"을 보여주고, 선점 알림에 그 세력 이름을 쓴다. 이 값은 1차에서 확률과 보상에 영향을 주지 않는다(표시와 알림만).

## 작업 목록

### 1. 데이터
- `cities.json`: 도시별 `maxActive`와 생성 빈도 값 조정(위 임시값), 도시별로 다르게 둘 수 있다.
- `rift-preemption.json`(이름은 구현자가 정해도 됨): 등급별 기본 확률, 마감 임박 보정 표(남은 일수 → 배율), 선점 제외 조건 설정.
- 새 리프트 등급, 새 세력을 행 추가로 늘릴 수 있어야 한다(등급 목록이나 세력 목록을 코드에 박지 않는다).

### 2. 엔진 (`src/engine/`, 화면 의존 금지)
- 리프트에 `territoryFactionId`(영역 세력)를 저장한다. 세이브 버전을 올리고 마이그레이션한다(기존 리프트는 영역 세력이 없을 수 있으니 없으면 도시 영향력 기준으로 시드 결정하거나 "미정"으로 표시. 구현자가 정하고 보고).
- 선점 판정 순수 함수(예: `rollPreemption(tables, state, 날짜)`): 위 규칙대로, 데이터만 쓴다.
- 하루 정산에 선점 판정과 `preempted` 이벤트(리프트 id, 이름, 세력 id)를 넣는다.
- 의미 검증과 스키마를 새 필드에 맞게 고친다.

### 3. 화면 (390×844 기준) — 많은 리프트를 고르기 쉽게
리프트가 서울 8, 도쿄 6, 뉴욕 7로 늘어도 한 도시의 목록이 길어져 못 고르는 일이 없어야 한다. [제안]
- **도시 칩**: 화면 위에 도시 칩(이름과 리프트 수, 마감 임박 수 배지). 지금 거점 도시가 기본으로 선택된다. (012에서 만든 칩 구성 요소를 재사용한다.)
- **요약 한 줄**: "마감 임박 N · 공략 가능(안전~해볼 만) N".
- **정렬과 필터**: 정렬은 마감 임박순(기본), 위험도순, 보상순, 등급순. 필터는 등급과 "위험도 해볼 만 이상만 보기". 012의 정렬·필터 방식과 같은 데이터 표 구조를 쓴다.
- **컴팩트 카드**: 기본은 두 줄 카드(1줄: 이름·등급·영역 세력, 2줄: 마감·위험도·보상 요약)로 한 화면에 더 많이 보이게 한다. 눌러서 기존 상세로 들어간다. 터치 영역 44px 이상, 글자 12px 이상.
- **상태 유지**: 상세에 들어갔다 돌아와도 도시·정렬·필터·스크롤 위치가 유지된다(세이브에는 저장하지 않는다).
- **홈**: 길드 홈에 "마감 임박 리프트 N개" 한 줄과 리프트 화면으로 가는 연결.
- **선점 알림**: 하루 결과 상단에 한 줄("⚔ ○○ 영역의 △△가 '리프트 이름'을 선점했습니다"). 여러 개면 이어서 쓴다.
- **위험도 계산 부담**: 카드가 늘어나므로 화면에 보이는 카드부터 계산하고 나머지는 한가할 때(예: `requestIdleCallback`) 계산한다. 엔진 메모이제이션은 유지한다. CPU 4배 제한에서 리프트 목록을 열 때와 정렬을 바꿀 때의 시간을 재서 보고하고, 200ms를 넘으면 방법을 정한다.

### 4. 테스트
- 선점: 같은 입력이면 같은 결과, 마감 임박일수록 확률이 오른다(표 값 기준), 안정화된 통로·출발한 리프트·그날 생긴 리프트는 판정하지 않는다, 데이터 값을 바꾸면 결과가 따라 바뀐다.
- 영역 세력: 같은 시드면 같은 세력, 가중치(영향력)가 0인 세력은 나오지 않는다, 기존 리프트 생성 결과(레벨·보상 등)는 변경 전과 같다(회귀).
- 세이브: 이전 버전에서 마이그레이션되고 의미 검증을 통과한다.
- 새 등급·새 세력을 가진 합성 데이터에서 코드 수정 없이 동작한다.
- 정렬·필터·도시 칩의 동작, 상세 왕복 후 상태 유지.
- 390×844 브라우저에서 리프트 화면(도시 칩, 정렬·필터, 컴팩트 카드), 홈 한 줄, 하루 결과의 선점 알림을 직접 확인하고 스크린샷을 보고한다.

### 5. 도구
- 도시별 평균 활성 리프트 수와 한도에 닿은 날 비율, 선점당한 비율(리프트 수명 동안)을 세는 출력을 `npm run days`나 새 도구(예: `npm run rift-stats`)에 추가해 위 표처럼 보고한다. 수치 조정은 하지 않고 임시값을 그대로 둔다(목표 평균 도달을 위한 값 조정만 허용).

## 하지 않는 것
- 세력 평판, 영입 경쟁 확대, 갈취, 라이벌 AI, 영토 점령은 만들지 않는다.
- 선점 경고(곧 뺏길 것 같은 리프트 표시)는 만들지 않는다.
- 전투, 경험치, 충성도, 시설 수치는 건드리지 않는다.
