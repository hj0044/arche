# 지시서 004-B: 1차 검수 반영 (편의와 UI)

004-A에 이어 편의 기능과 모바일 UI를 개선한다. Codex 1차 검수(`docs/reviews/2026-11-20-1차검수.md`)의 UI·UX 의견과 균형 의견 가운데 도구로 풀 수 있는 부분을 다룬다. 정본은 설계서이고, 결정은 설계서 변경 로그의 2026-11-20 행이다. 문서와 코드가 다르면 문서가 맞다. 충돌하거나 비어 있는 곳은 임의로 정하지 말고 `docs/open-questions.md`에 적고 보고한다.

**시작 전 확인**: 004-A가 main에 들어간 뒤에 시작한다. 004-A가 아직이면 멈추고 보고한다.

## 새로 확정된 규칙 (사용자 결정, 2026-11-20)

- [확정] 편성 화면에 자동 편성 기능을 둔다. 규칙은 [제안]이라 바꿀 수 있고, 바꾸면 보고한다.
- [확정] 파견은 버튼 한 번으로 보내고 별도 확인 창은 두지 않는다. 대신 편성 화면에 복귀 예정일을 보여준다.

## 작업 목록

### 1. 자동 편성

- 편성 화면에 "자동 편성" 버튼을 둔다. 결과는 편성 칸에 채워지고 사용자가 직접 고칠 수 있다.
- 규칙 초안: 가용 용병(부상, 파견 중 제외)에서, 선택한 리프트의 알려진 정보(속성 상성)와 구성 보너스(전위, 딜러, 지원)를 기준으로 고른다. 후보 점수와 가중치는 데이터 표로 둔다.
- 엔진의 순수 함수로 만들고(`src/engine/`), 같은 입력이면 같은 결과가 나온다. 동점은 용병 id 순으로 정한다.
- 개방자 모드에서 주인공은 가용하면 포함하는 쪽으로 한다. 이 선택은 보고한다.
- 테스트: 결정성, 부상·파견 중 제외, 가용 인원 부족 시 있는 만큼만 편성, 전위·딜러·지원이 가능하면 모두 갖춤.

### 2. 파견 복귀일 표시

- 확인 창은 두지 않는다. 편성 화면에 복귀 예정일(또는 소요 일수 범위)과 현재 길드 하루 유지비를 보여준다.
- 복귀 예정일이 확정값인지 범위인지는 리프트 데이터에 따른다. 어느 쪽인지 보고한다.

### 3. 영입 확인에 유지비 표시

- 영입 확인 화면에 "영입 후 길드 하루 유지비"와 "수입 없이 버틸 수 있는 일수"를 보여준다. 계산은 엔진 함수로 만들고 화면은 값만 표시한다.

### 4. UI 개선 (390×844 기준)

- 인접 컨트롤(전열/후열 이동, 빼기, 도시와 모드 전환)의 세로 터치 영역을 44px 이상으로 맞춘다.
- 편성 화면: 후보를 추가해도 다음 후보가 밀리지 않게 한다. 편성 요약은 화면에 고정하거나 후보 목록 위에 짧게 둔다.
- 리프트 카드: 첫 줄에 레벨, 마감, 소요를 우선 두고, 몬스터 목록과 보상 세부는 접어 둔다. 한 손으로 읽기 쉬운 밀도를 목표로 한다.
- 전투 재생
  - 같은 이름의 몬스터는 번호를 붙여 구분한다(예: 껍데기 수호자 1, 2).
  - 열 카드는 인원 수에 맞춰 폭을 늘려 이름이 잘리지 않게 한다.
  - 최신 행동은 고정된 한 줄로 보여주고, 누적 로그는 라운드별로 묶는다.
  - ×4 속도에서 놓친 행동을 볼 수 있게 한 행동씩 넘기기(스텝)를 둔다. [제안]
- UI 변경은 390×844에서 직접 보고 확인한다. 색만으로 구분하지 않는다.

### 5. 새 게임 화면

- 필수 입력(길드 이름, 주인공 이름, 시작 도시, 모드)을 첫 화면 위쪽에 두고, 세부 선택은 접어 둔다. 스크롤 없이 시작 버튼까지 닿는지 390×844에서 확인한다.

### 6. 밸런스 도구 보강 (수치는 바꾸지 않는다)

- `npm run balance`에 시작 조합 4인 표본을 추가한다(예: Lv5 시작 역할 조합 4인 vs 하급 Lv12 3마리, 중급 Lv15 3마리, 중급 Lv20 3마리). 합법 등급 범위 안의 조건만 쓴다.
- `npm run days` 요약에 용병별 출전 횟수와 승률을 추가해, 영입 후 특정 용병의 쏠림을 볼 수 있게 한다.
- 이 도구는 플레이 후 수치를 조정할 때의 근거 자료다. 도구가 보여주는 값을 바꾸는 작업은 하지 않는다.

## 하지 않는 것

- 수치 조정(영입비, 유지비, 몬스터 레벨 범위, 성장 곡선)은 하지 않는다. 밸런스는 사용자의 플레이 이후에 정한다.
- 카게야마 쇼(12번) 조정, 징조 시스템, 2단계 이후 기능은 건드리지 않는다.
- 설계서와 설정집은 고치지 않는다. 충돌과 공백은 보고만 한다.

## 완료 기준

- 위 항목 중 엔진 로직(자동 편성, 유지비 계산)에는 테스트가 있고 `npm test`, `npm run typecheck`, `npm run build`가 통과한다.
- 직접 실행해서 확인한다: 자동 편성, 편성 화면의 복귀일, 영입 확인 화면, 전투 재생(스텝 포함), 새 게임 화면, `npm run balance`, `npm run days`.
- 결정성이 깨지지 않았는지 `npm run days`로 같은 시드 결과를 비교한다.
- 보고는 한국어로, 항목별 한 줄과 함께 바꾼 결정(자동 편성 규칙, 복귀일 표시 방식), 문서와 충돌한 곳, 확인하지 못한 것을 적는다.
