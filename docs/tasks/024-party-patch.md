# 지시서 024: 파티 편성 국소 패치 (탭 해제 · 끌기 배치 · 레벨/한계 표시)

전제: 022·023이 머지된 상태. `PartyBuilder.tsx`와 파티 슬롯/카드 컴포넌트만 바꾸는 작은 패치다. 시안: `docs/design/ui/Party.html`(배지), `PartyDrag.html`(끌기 중 모습), `contract.json`의 `Party`가 정본이다. 엔진은 바꾸지 않는다.

## 1. 레벨/성장 한계 배지
- 전열·후열 슬롯 카드와 대기 계약자 카드의 레벨 숫자를 `레벨/성장 한계`(예 11/50)로 바꾼다(`data-ui="party.level"`). 계약자 화면·영입 카드의 배지(17c)와 같은 모양·같은 한계 계산을 쓴다.
- 슬롯 카드는 62px 폭이라 글자 12px 굵게, 줄바꿈 없이 들어가야 한다(성장 한계 두 자리까지). 넘치면 폭이 아니라 패딩을 줄인다.

## 2. 탭하면 바로 해제
- 편성된 계약자를 탭하면 **바로 파티에서 빠진다**: 슬롯 카드 탭, 대기 목록의 '편성됨' 카드 탭 모두. 해제 후 가벼운 토스트("○○ 해제") 한 번.
- 기존의 "전열로 옮기기/후열로 옮기기/파티에서 빼기" 바텀 시트는 없앤다(끌기로 대체). 편성되지 않은 계약자의 시트(훈련 해제, 출전 불가 사유)는 그대로 둔다.
- 빈 칸 탭은 지금처럼 안내 토스트.

## 3. 끌기로 배치·교체
세로 모바일 터치 기준이고, 마우스도 같은 동작이어야 한다. 포인터 이벤트로 구현하고 새 라이브러리는 쓰지 않는다.
1. **시작**: 카드를 **길게 누르면**(약 250ms, 데이터 표에 둔다) 끌기가 시작된다. 길게 누르기 전의 세로 이동은 스크롤로 취급한다. 끌기 중에는 페이지 스크롤과 화면 스와이프(탭 간 이동)를 막는다(`data-noswipe`).
2. **모양**: 끄는 카드는 손가락 위에 살짝 커지고 기울어진 사본(`party.ghost`)으로 따라오고 원래 칸은 흐려진다. 놓을 수 있는 칸은 금색 테두리와 은은한 빛(`party.dropTarget`)으로 강조한다. 위쪽에 "놓을 칸을 고르세요 · 대기 목록에 놓으면 해제" 안내를 띄운다. 시안과 같게.
3. **놓는 곳별 동작**
   - 빈 칸(전열/후열): 그 열로 이동(대기 계약자면 새로 편성). 열이 꽉 찼으면 놓을 수 없는 칸으로 표시(강조 없음, 놓으면 토스트 "전열은 5명까지").
   - 채워진 칸: **자리 교체**. 같은 열이면 순서만 바뀌고, 다른 열이면 서로의 열이 바뀐다. 대기 계약자를 채워진 칸에 놓으면 그 칸의 계약자가 해제되고 그 자리에 들어온다(열 유지).
   - 대기 목록 구역: 편성된 계약자는 해제된다. 대기 계약자를 대기 목록에 놓으면 아무 일도 없다.
   - 그 밖의 곳이나 취소(끌기 도중 화면 밖, ESC): 원래대로 돌아간다.
4. **슬롯 위치 규칙**: 열 안의 순서는 파티 배열 순서이고 빈 칸은 뒤에 모인다. 빈 칸 중 어디에 놓아도 열의 맨 뒤에 붙는다(칸 번호를 따로 저장하지 않는다). 순서를 바꾸는 방법은 채워진 칸과의 교체뿐이다.
5. 출전 불가 계약자(부상, 파견 중, 훈련 중, 오늘 거부)는 끌 수 없고, 누르면 지금처럼 사유 시트가 열린다.
6. 짧은 탭은 끌기로 보지 않는다(2번의 탭 해제와 충돌하지 않는다). 끌기를 끝낸 직후의 클릭 이벤트는 무시한다.
7. 접근성: 끌기가 어려운 사람을 위해 같은 일을 키보드(포커스한 카드에서 방향키로 이동 칸 선택, Enter로 놓기)로 할 수 있게 하되, 화면 표시는 시안과 같다. 시안에 없는 새 버튼은 만들지 않는다.

편성 계산(전투력, 위험도, 승률, 구성 보너스)은 파티 상태가 바뀔 때마다 기존 방식대로 다시 계산한다. 끌기 도중에는 계산하지 않고 놓은 뒤 한 번만 한다.

## 4. 하지 않는 것
엔진·편성 규칙(최대 인원, 열당 5명, 기본 열) 변경, 자동 편성 변경, 새 화면, 시안에 없는 버튼, 파티 저장·불러오기 기능.

## 5. 테스트와 보고
- 순수 함수 `src/ui/partyDrag.ts`로 놓기 규칙(빈 칸 이동, 열 꽉 참, 같은 열 교체, 다른 열 교체, 대기→채워진 칸 대체, 대기 목록에 놓아 해제, 출전 불가)을 분리해 단위 테스트한다. 해제 후 재편성, 5+5 한도, 같은 계약자 중복 편성 불가를 검사한다.
- `ui:check`에 `party.level` 표기 형식(`N/M`)과 폭 넘침 없음, `party.ghost`·`party.dropTarget`이 끌기 중에만 존재하는지(Playwright로 끌기 흉내) 검사를 추가한다. 터치 영역 44px 규칙은 슬롯에도 적용한다(기존 시안 크기 유지).
- `ui:shots`에 파티 편성(기본)과 끌기 중 화면을 추가해 시안과 compare 이미지를 만든다. `npm test`·`typecheck`·`build`.

## 6. 완료 조건: 머지와 배포까지 (AGENTS.md 확정 규칙, 이 지시서의 일부)
1. 위 검사가 통과한 PR을 연다(테스트, 타입 검사, 빌드, `ui:check`).
2. 사용자 확인을 기다리지 않고 바로 `main`에 머지한다. 결정이 필요한 항목은 PR 본문과 `docs/open-questions.md`에 적되 머지를 막지 않는다.
3. Render 배포가 `live`가 된 것을 확인한다. 실패하면 고쳐 다시 머지한다.
4. 최종 보고는 "배포 완료", 배포 커밋, compare 이미지(파티 편성, 끌기 중), 미해결 결정 목록으로 한다.
