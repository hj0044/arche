# 지시서 003: 흑막 징조 표식

1단계에서 흑막의 존재감을 보여주는 "징조 표식"을 넣는다. 정의는 설정집 용어집의 "징조 표식", 결정은 설계서 변경 로그(2026-11-19 마지막 행들)가 정본이다. 문서와 코드가 다르면 문서가 맞다. 충돌하거나 비어 있는 곳은 임의로 정하지 말고 `docs/open-questions.md`에 적고 보고한다.

## 확정된 범위

- [확정] 1단계는 징조 표식과 짧은 문구만 보여준다. 이것은 연출이고 시스템이 아니다.
- [확정] 몬스터는 이미 공허 쪽이므로 전투, 보상, 난이도 규칙은 바뀌지 않는다. 표식은 규칙에 영향을 주지 않는다.
- [확정] 징조가 단계적으로 진행되는 시스템(공허 농도, 간부급 출현, 본체 출현)은 확장이다. 1단계에서 만들지 않는다. 나중에 얹을 자리만 막지 않는다.
- [제안] 표식은 항로(최상급) 등급 리프트에만 붙인다. 바꿔도 되지만 보고한다.

## 작업 목록

### 1. 데이터

- 리프트 등급 데이터(`rift-tiers.json` 등)에 등급별 표식 확률을 둔다. 임시값은 균열 0, 관문 0, 항로 1.0이다. 수치는 코드에 박지 않는다.
- 리프트가 생길 때 표식 여부를 시드로 정해 리프트 상태에 저장한다. 같은 시드면 같은 리프트에 같은 표식이 붙어야 한다.
- 표식 문구는 데이터 표로 둔다. 짧은 문구 3~4개를 임시로 쓰고(예: 공허 이상 징후를 설명하는 한 줄), 리프트마다 시드로 하나를 고른다. 문구는 임시이니 `open-questions.md`에 적는다.
- 새 등급이나 새 문구는 데이터 행 추가로 늘릴 수 있어야 한다.

### 2. 세이브

- 표식 여부와 문구 id는 세이브에 저장하고 불러온 뒤에도 유지된다.
- 필드를 추가하면 세이브 버전을 올릴지, 없는 값을 기본값(표식 없음)으로 읽을지 정하고 이유를 보고한다. 이전 세이브를 폐기해도 되는지는 사용자가 결정한 방침(개발 중에는 호환을 무시)을 따른다.

### 3. 화면 (390×844 세로 기준)

- 리프트 목록과 리프트 상세에 표식을 보여준다: 아이콘이나 배지와 짧은 문구. 색만으로 구분하지 말고 글자도 함께 쓴다.
- 파견 복귀 보고에 표식이 있던 리프트였다는 한 줄을 넣는다.
- 목록의 정보 밀도가 늘어나므로 한 손 조작과 터치 영역을 해치지 않는지 확인한다.
- 화면에는 "공허"가 아닌 표기명 규칙을 따른다(속성 표기명은 AGENTS.md 참조). 문구에 속성 이름이 필요하면 화면 표기명을 쓴다.

### 4. 테스트

- 같은 시드와 같은 입력이면 같은 리프트에 같은 표식과 문구가 붙는다.
- 항로에만 표식이 붙고 균열과 관문에는 붙지 않는다(임시 확률 기준).
- 세이브와 불러오기 후에도 표식이 유지된다.
- 표식이 전투 결과와 보상에 영향을 주지 않는다(같은 시드에서 표식 유무만 달라도 결과가 같다).

## 하지 않는 것

징조 단계 진행, 공허 농도, 도시별 징조 수치, 간부급과 본체 출현, 표식으로 인한 난이도나 보상 변화는 만들지 않는다. 확장에서 쓸 자리만 막지 않는다.

## 완료 기준

- 새 게임에서 항로 리프트가 열리면 목록과 상세에 표식과 문구가 보인다.
- 균열과 관문에는 표식이 없다.
- 테스트와 타입 검사가 통과하고, 세로 모바일 화면에서 직접 확인했다.
- 임시로 정한 것은 모두 `docs/open-questions.md`에 적었다.
