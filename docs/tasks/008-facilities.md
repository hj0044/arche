# 지시서 008: 거점 시설 (의무실, 훈련소, 탐지소)

2단계의 두 번째 기능인 거점 시설을 구현한다. 정본은 설계서의 "거점 시설" 절과 변경 로그 2026-11-20 마지막 행이다. 문서와 코드가 다르면 문서가 맞다. [확정]은 지켜야 하는 규칙, [제안]은 바꿔도 되지만 보고, [미정]은 구현하지 말고 질문한다. 충돌하거나 비어 있는 곳은 임의로 정하지 말고 `docs/open-questions.md`에 적고 보고한다.

**시작 전 확인**: 007(충성도 확장)이 main에 들어간 뒤에 시작한다(이미 들어갔을 것이다). 아니면 멈추고 보고한다.

## 확정된 규칙 (사용자 결정, 2026-11-20)

- [확정] 거점은 시작 도시 한 곳이다. 도시별 지부는 확장이다. 만들지 않는다.
- [확정] 시설 목록은 고정된 데이터 표이고, 시설마다 레벨이 있다. 칸 수 제한은 없다. 시설과 레벨은 데이터 행을 추가해 늘리고, 최대 레벨도 데이터로 정한다. 표에 없는 레벨은 공식(기본값과 증가율)으로 계산해서, 최대 레벨을 올리는 일이 코드 수정 없이 데이터만으로 된다.
- [확정] 이번에 구현하는 시설은 의무실, 훈련소, 탐지소 3개다. 정제소와 개조 공방은 쓰임이 정해진 뒤에 한다. 개조 공방이 나중에 훈련소처럼 용병을 배치하는 방식으로 이어질 수 있게 "시설에 용병을 배치한다"는 부분은 시설 종류에 묶이지 않게 만든다.
- [확정] 훈련소에는 용병을 배치해 일을 시킨다. 부상 중인 용병은 배치할 수 없다.
- [확정] 탐지소는 레벨에 따라 리프트 정보가 정확해진다. 시작할 때 탐지소 Lv1을 준다.
- [제안] 건설과 강화는 제로와 N일이 든다. 한 번에 한 시설만 건설·강화할 수 있다. 비용과 일수는 임시값이다.

## 작업 목록

### 1. 데이터 (모든 수치는 표로 분리, 아래 값은 임시)

`facilities.json` 같은 표를 만든다. 모양은 구현자가 정하되 다음을 지킨다.

- 시설마다: id, 이름, 설명, 최대 레벨(`maxLevel`), 건설·강화 비용 공식(기본 제로, 증가율, 기본 일수, 일수 증가), 레벨별 덮어쓰기 행(선택), 효과 종류와 레벨별 효과값.
- 최대 레벨을 올릴 때 표 행을 늘리지 않아도 공식으로 비용·일수·효과가 계산되어야 한다(효과가 표 기반이면 마지막 행을 이어받는 규칙을 쓴다). 이 동작을 보장하는 테스트를 만든다(6항).
- 새 시설은 효과 종류가 기존 것이면 데이터 행만으로 추가된다. 새 효과 종류가 필요하면 코드에 효과 처리기를 등록하는 한 곳만 건드린다.
- 임시값
  - 비용: Lv1 제로 150, 일수 2. 레벨이 오를수록 제로 ×1.8, 일수 +1. 최대 레벨은 시설마다 3.
  - 의무실: 레벨당 부상 일수 −1(치유사 효과와 합산, 최소 1일). 새로 입은 부상에만 적용한다.
  - 훈련소: 배치 칸 = 레벨. 배치된 용병은 매일 경험치를 얻는다(하루 10 + 5 × (레벨 − 1), 임시). 성장 한계에 이른 용병은 얻지 않는다.
  - 탐지소(시작 Lv1): Lv1은 몬스터 속성을 공개하고 마감일은 실제 ±1일 범위, 몬스터 레벨과 수는 범위로 흐리게 보인다. Lv2는 몬스터 레벨·수·마감일 정확. Lv3은 보상 정확과 징조 표식 공개. Lv1~2의 보상은 범위로 보이고 폭은 데이터로 둔다.
- 흐림 범위의 폭과 형태는 데이터로 둔다. 표시는 범위(예: "Lv 12~16", "2~3마리", "마감 3~5일차")이고, 숨기는 값을 "?"로만 표시하는 경우(징조 표식)는 구현자가 정한다.

### 2. 엔진과 세이브

- 세이브에 시설 상태(시설별 레벨), 진행 중인 건설·강화(대상, 완료일), 훈련소 배치(용병 id 목록)를 저장한다. 세이브 버전 처리는 구현자가 정한다(버전을 올리고 마이그레이션 권장: 기존 세이브는 탐지소 Lv1, 나머지 Lv0, 큐 없음, 배치 없음). 스키마와 의미 검증도 맞춘다. 이유를 보고한다.
- 건설·강화: 시작할 때 제로를 즉시 차감하고, 완료일이 되면 하루 정산에서 레벨을 올린다. 한 번에 한 시설만 진행한다. 제로가 모자라거나 이미 진행 중이거나 최대 레벨이면 거부한다. 취소는 없다(환불 없음) [제안]. 바꾸면 보고한다.
- 의무실: 새로 입은 부상 일수 계산에 시설 효과를 반영한다. 이미 부상 중인 용병에게는 소급 적용하지 않는다.
- 훈련소: 길드 소속, 주인공 제외, 부상 중이 아님, 파견 중이 아님인 용병만 배치할 수 있다. 배치된 용병은 파견 편성과 자동 편성에서 제외된다. 배치 해제는 즉시 가능하다(해제 시점은 구현자가 정하고 보고). 부상을 입거나 이탈하면 자동으로 해제된다. 경험치는 하루 정산에서 지급한다(레벨업은 지금처럼 아르케를 내는 수동 방식 그대로).
- 충성도와의 관계: 훈련 중인 날은 쉰 날로 세지 않는다. 연속 쉰 일수(`restStreak`)는 0으로 두고 쉬는 날 상승도 대기 하락도 적용하지 않는다. 충성도가 변하지 않는다.
- 탐지소: 리프트의 실제 값은 바꾸지 않고 "보이는 정보"만 만든다. 순수 함수(예: `visibleRift(rift, facilities)`)로 엔진에 두고 화면이 이것만 쓴다. 흐림 범위는 리프트가 생길 때 정한 오프셋을 리프트 상태에 저장해, 볼 때마다 값이 흔들리지 않게 한다(시드 기반, 결정적). 저장 필드 추가는 세이브 처리에 포함한다.
- 자동 편성은 "보이는 정보"만 사용한다(정확한 숨은 정보를 몰래 쓰지 않는다).
- 모든 난수는 시드 기반이다. 같은 입력과 같은 시드면 같은 결과다.

### 3. 화면 (390×844 세로 기준)

- 거점 화면: 시설 카드 목록(이름, 현재 레벨, 다음 레벨의 효과·비용·일수, 진행 중이면 남은 일수). 건설·강화 버튼은 제로 부족과 진행 중 상태를 이유와 함께 비활성 표시한다. 시설 수와 레벨 수가 늘어도 레이아웃이 깨지지 않게 한다(레벨 수를 3으로 가정하지 않는다).
- 훈련소 배치: 배치된 용병 목록과 해제, 배치할 용병 선택(부상, 파견 중, 주인공은 이유와 함께 선택 불가). 칸 수는 레벨에서 온다.
- 리프트 카드와 상세: 탐지소 레벨에 따른 흐림 표시. 흐린 정보에는 "탐지소 레벨을 올리면 더 자세히 보임" 같은 안내를 한 번 보여준다. 색만으로 구분하지 않는다.
- 하루 결과: 건설·강화 완료, 훈련소 경험치 요약.
- 터치 영역 44px 이상, 정보 밀도가 늘어나므로 접기와 요약을 쓴다. 속성 표기명 규칙은 AGENTS.md를 따른다.

### 4. 자동 플레이 정책 (`npm run days`용)

- 자동 플레이는 제로 여유가 있을 때(영입보다 우선순위는 구현자가 정하고 보고) 의무실 → 훈련소 → 탐지소 순으로 올리고, 훈련소 칸에 대기 중인 용병을 배치한다. 정책 값은 데이터로 둔다.
- `npm run days`와 `npm run loyalty-sweep` 요약에 시설 레벨, 훈련 경험치 합계, 미납·이탈 수가 나오게 한다. 시설이 경제와 충성도 흐름을 어떻게 바꾸는지 007 비교표와 견줄 수 있게 한다.

### 5. 문서 정리

- 새로 정한 것들을 `docs/open-questions.md`에 적는다. 설계서와 설정집은 고치지 않는다.

### 6. 테스트

- 레벨 확장: 합성 데이터(레벨 7개, 새 시설 하나)로 코드가 레벨 수 3과 시설 수 3을 가정하지 않는지 확인한다. 최대 레벨만 올려도 비용·일수·효과가 공식으로 계산된다.
- 건설: 한 번에 하나, 제로 부족 거부, 완료 시점의 레벨 반영, 완료 후 다음 건설 가능, 최대 레벨 거부.
- 의무실: 부상 일수 계산(치유사 합산, 최소 1일), 이미 부상 중인 용병에는 소급 안 됨.
- 훈련소: 배치 조건(부상, 파견 중, 주인공, 칸 수), 파견·자동 편성 제외, 경험치 지급, 성장 한계 용병은 지급 없음, 충성도 변동 없음, 부상·이탈 시 자동 해제.
- 탐지소: 레벨별 공개 항목, 흐림이 결정적이고 볼 때마다 같음, 실제 값은 불변, 자동 편성이 보이는 정보만 사용, 징조 표식 공개는 Lv3.
- 세이브: 마이그레이션, 왕복, 의미 검증.
- 결정성 회귀 확장: 건설 진행과 훈련 배치가 있는 길드에서 15일 동안 매일 저장 왕복하며 상태·이벤트가 같다.

## 하지 않는 것

- 정제소, 개조 공방, 도시별 지부, 일반병사는 만들지 않는다. 나중에 얹을 자리만 막지 않는다.
- 수치 최종 조정은 하지 않는다. 위 수치는 임시값이고 사용자의 플레이 이후에 정한다.
- 설계서와 설정집은 고치지 않는다. 충돌과 공백은 보고만 한다.

## 완료 기준

- 위 항목마다 테스트가 있고 `npm test`, `npm run typecheck`, `npm run build`가 통과한다.
- 직접 실행해서 확인한다(390×844): 시설 건설과 강화, 훈련소 배치와 경험치, 의무실 부상 일수, 탐지소 레벨별 정보 흐림과 안내 문구, 하루 결과.
- `npm run days`로 결정성을 확인한다(같은 시드 두 번 실행 결과 일치).
- 보고는 한국어로, 항목별 한 줄과 함께 구현자가 정한 것(세이브 버전 처리, 배치 해제 시점, 자동 플레이의 시설 우선순위, 흐림 표시 형태), 문서와 충돌한 곳, 확인하지 못한 것, 시설이 미납과 이탈에 준 영향을 적는다.
