# 지시서 014: Codex 3차 검수(충성도·거점 시설) 반영

근거: `docs/reviews/2026-11-21-충성도-거점시설-검수.md`(브랜치 `docs/2026-11-21-loyalty-facilities-review`). 013을 끝낸 뒤 이어서 진행한다(둘 다 화면 파일을 만진다).

## 확정된 것 (사용자 결정, 2026-11-21) [확정]
- 훈련 중에도 미납 하락은 적용된다. 훈련은 휴식 감쇠(대기 하락)만 막는다.
- 돈이 모자란 날은 충성도가 낮은 용병부터 유지비를 먼저 낸다. 같으면 용병 id 순.
- 복귀 보상은 그날 유지비보다 먼저 반영한다(이긴 날 보상으로 유지비를 낼 수 있다).
- 철수는 충성도를 직접 바꾸지 않는다(승리·패배 변동 없음). 철수로 생긴 부상과 미납은 각각 정산한다.
- 수치(충성도 변동, 확률, 유지비, 경험치)는 이번에 바꾸지 않는다.

## 작업 목록

### 1. 유지비 처리 순서 (`src/engine/game.ts`)
- 납부 루프를 충성도 낮은 순(동점 id 순)으로 돈다.
- 복귀 보상이 유지비보다 뒤에 들어오는 곳이 있으면 앞으로 옮긴다. 순서가 복잡해 구조를 크게 바꿔야 하면 멈추고 보고한다.
- 이 변경은 같은 시드의 결과를 바꾼다. 세이브 형식은 그대로라 버전은 올리지 않는다. 결정성 테스트(저장 왕복 비교)는 새 순서 기준으로 통과해야 한다.

### 2. 세이브 의미 검증 (`src/storage/saveSemantics.ts`)
- 진행 중 공사는 `startDay ≤ state.day < completeDay`를 검사한다. 어긋나면 오류 메시지와 함께 불러오기를 거절한다.
- 지금 버전으로 정상 플레이해 만든 세이브는 모두 통과해야 한다. 옛 버전 세이브는 신경 쓰지 않는다.

### 3. 탐지소 Lv1 마감 범위: 코드는 그대로
- 마감 범위는 폭 2일이고 실제 마감은 그 안에 있다. 위치는 리프트마다 무작위다(범위의 가운데가 곧 정답이 되지 않게 하려는 설계다). 지시서나 설명의 "±1일" 표현은 "폭 2일"로 정리한다.
- 테스트: 어떤 리프트든 실제 마감이 표시 범위 안에 있다.

### 4. 테스트
- 미납과 훈련이 같은 날 겹치면 경험치는 받고 충성도는 미납만큼 깎인다.
- 유지비가 모자란 날 낮은 충성도 용병부터 낸다. 동점이면 id 순이다.
- 복귀 보상으로 그날 유지비를 낼 수 있는 경우 미납이 생기지 않는다.
- 철수에는 승리·패배 변동이 붙지 않는다.
- 미래에 시작하는 공사 세이브는 불러오기에서 거절된다.

### 5. 화면 (390×844 기준)
- 충성도 상세(`MercDetail.tsx`): 경고·수치와 급료 보너스 버튼이 첫 화면에 함께 보이게 한다. 최근 기록은 최신 1~2행만 보이고 나머지는 펼치기로 둔다. 버튼 높이 44px 이상은 유지한다.
- 거점 시설(`Base.tsx`): 카드 기본 정보는 현재 레벨, 다음 행동, 진행 상태로 줄인다. 현재·다음 효과 비교와 배치 후보 목록은 펼쳐서 본다. 비용과 일수가 카드와 버튼에 중복으로 나오지 않게 한다.
