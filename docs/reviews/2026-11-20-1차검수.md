- 날짜: 2026-11-20
- 검수자: Codex
- 종류: 오류
- 심각도: 중간

#### 위치

`src/storage/saveFile.ts:43–73`, `src/storage/saveService.ts:86–90`, `src/ui/screens/SaveSlots.tsx:77–85`, `src/engine/game.ts:484–497`.

#### 설계서 근거

1단계 명세 §9 세이브 [확정], 002 §6 세력 이름 및 세이브 버전 변경 [확정], 001 M4 세이브 스키마.

#### 현상

가져오기에 성공한 세이브는 진행을 재개할 수 있어야 한다. 파서는 상태 필드 가운데 날짜·시드·배열 세 개만 검사한다. 필수 `resources`가 빠진 v2 사본도 파서를 통과하며, 그 상태로 하루를 넘기면 `zero`를 읽다가 TypeError가 발생한다. 파일 가져오기는 이 검사를 통과하면 슬롯에 먼저 기록한다. 원본을 다시 가져오면 복구할 수 있다.

#### 재현 방법

- 시드: `audit-20261120`
- 세이브(JSON 또는 파일 위치): 부록의 `/tmp/arche-audit-v2.json`에서 `state.resources`만 삭제한 사본.
- 순서: 사본을 `parseSave`에 넣고 반환된 `state`를 `advanceDay`에 전달한다. 파싱은 성공하고 진행에서 `Cannot read properties of undefined (reading 'zero')`가 발생한다. UI 진입점은 불러오기 → 파일에서 불러오기다.

#### 제안

슬롯 기록 전에 봉투와 필수 상태 필드를 검증하고, 오류에 필드 경로를 표시한다. v1 거부 정책과 연결해 정상 v2, 이전 버전, 손상된 v2를 각각 검증한다.

#### 현상

#### 재현 방법

- 시드: 자동 저장은 `audit-20261120`, 안정화 통로는 시드 무관.
- 세이브(JSON 또는 파일 위치): `/tmp/arche-audit-v2.json`. 안정화 문구를 보려면 `state.rifts`의 확인 대상 항목에 `"stable": true, "deadlineDay": null`을 설정한 화면 검증용 사본을 사용한다.
- 순서: 날짜를 네 번 넘겨 자동 저장 네 건 중 최신 3건만 남고 화면도 3개를 안내하는지 확인한다. 리프트 문구는 `stablePassageRewardRatio` 참조 여부를 소스에서 대조한다.

#### 제안

저장 개수는 읽기 전용 정책 데이터로 한 번 정의하고 문구에서 같은 값을 읽는다. 안정화 통로의 안내는 정산 배율로 생성한다.

## 부록 — 재현 입력

저장소 루트에서 의존성을 설치한 후 다음 명령으로 공통 파일을 만든다. 내보내기·불러오기의 이름이나 시각과 무관하게 같은 상태와 시드를 재현할 수 있다.

```bash
./node_modules/.bin/tsx -e '
import { writeFileSync } from "node:fs";
import { tables } from "./src/data";
import { newGame } from "./src/engine/game";
import { createSaveFile } from "./src/storage/saveFile";
const state = newGame(tables, {
  seed: "audit-20261120",
  guildName: "검수 길드",
  baseCityId: "seoul",
  protagonist: {
    mode: "opener", name: "검수자", element: "fire",
    role: "warrior", background: "survivor"
  }
});
writeFileSync("/tmp/arche-audit-v2.json", JSON.stringify(
  createSaveFile(state, "manual", new Date("2026-11-20T00:00:00Z")), null, 2
));
'
```

- 보충 전투: 세이브의 `hero,m02,m03,m04`를 기본 열에 둔다. 조건별 같은 레벨로 `mercToUnit`을 생성한다. 5인 비교에서는 마지막에 `m12`, `m16`, `m18`, `m26` 중 한 명을 기본 열에 추가한다. 적은 전사·방패·사수·술사 순서에서 필요한 수만 골라 요청한 등급·레벨·공허 속성·기본 열로 생성한다. 각 시드 `b0`~`b39`로 `resolveCombat`을 호출한다.
- 비교 경제: `scripts/days.ts`의 서울 개방자 시작과 레벨업 정책을 사용한다. 영입을 생략하고 서울의 하급 균열 중 최저 레벨만 선택하며, 가용 인원 3명 이상일 때 최대 4명을 기본 열로 보내고 40번 날짜를 넘긴다. 미납 일수는 `upkeep.unpaid > 0`인 날짜 수다.
- 결정성: 고정 v2의 `r1`에 파견한 상태를 복제한다. 한쪽은 메모리 상태, 다른 쪽은 `createSaveFile → JSON.stringify → parseSave`를 사용한다. 두 상태에서 각 10회의 `advanceDay` 반환값(상태·이벤트)을 깊은 비교한다.
